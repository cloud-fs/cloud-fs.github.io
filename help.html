装好之后第一件事

在浏览器里打开

http://<主机 IP>:19798

核心服务的管理界面跑在 19798 上——无论装在 Windows、Linux、macOS、Android 还是 Docker 里都一样。装在本机就用 http://localhost:19798。

另有一个 HTTPS 端口 19799，默认关闭，要在设置里打开并配置证书。

应用自带的核心监听 29798，和核心服务错开——同一台机器上两个一起装，端口不会冲突。

管理界面整个是一个 WebAssembly 应用，所以浏览器必须支持 WebAssembly，不支持的直接白屏，不是「部分功能用不了」。电脑上用较新版本的 Edge、Chrome、Safari 或 Firefox 都可以，手机和平板上的主流浏览器也可以。Internet Explorer 不行；电视自带的浏览器、以及一些机顶盒、电子书和车机上的精简浏览器也多半不行——那些设备请改用手机或电脑打开，或者直接装对应平台的应用。

第一步

安装与运行

这一节讲的是把核心装成后台服务：电脑、NAS 或路由器都行。手机、电视和头显上的应用自带同一套核心，不需要另外架服务器，见在手机和电视上用。

Windows
  1. 到下载页拿对应架构的安装包（x64 或 Arm64）。
  2. 打开安装包，按屏幕上的提示完成安装。
  3. 安装完成后，桌面上会出现 CloudDrive2 快捷方式。双击它，或者直接在浏览器里打开 http://localhost:19798。
上次跑完整安装包时早于 1.0.7 的，要再跑一次

1.0.7 把随包的 WinFSP 驱动升到了 2026 beta1，修掉旧版 WinFSP 的安全漏洞 CVE-2026-3006。应用内 OTA 只替换 CloudDrive2 自己的程序文件，从不碰驱动。

所以看的不是你现在是哪个版本，而是上一次跑完整安装包时是哪个版本。那次要是早于 1.0.7，哪怕之后一路 OTA 升到了最新版，驱动也仍然是旧的——请下载完整安装包重新运行安装程序，并按向导提示重启系统。记不清就再跑一次，没有副作用。

上次完整安装的是 1.0.7 或更高版本的，驱动已经是修好的那一版，之后的升级用应用内 OTA 就行。

它以系统服务的方式在跑

核心服务装完就注册成 Windows 系统服务，开机自启，不用登录桌面也在跑。Windows 应用不一样，它是普通应用，跟着你的账户启动。

安装包、服务和 WinFSP 驱动都经过代码签名，但个别杀毒软件仍可能拦下其中之一——服务起不来、挂载盘出不来，或者应用直接被关掉。遇到这种情况，把 CloudDrive2 的安装目录和 WinFSP 一起加进杀软白名单。管理界面打不开时的完整排查顺序见常见问题。

要从局域网里的别的设备访问，Windows 防火墙得放行对应端口：核心服务是 19798（开了 HTTPS 再加 19799），应用是 29798。装的时候通常会弹一次「允许访问」，点掉了的话到「Windows 安全中心 → 防火墙和网络保护 → 允许应用通过防火墙」补上。

Windows 7 已停止支持——系统自带的 TLS 和运行库满足不了当前版本的要求。旧设备可以改用 Linux 或 Docker 版本。

Linux 通用
  1. 确认内核支持 FUSE。看一下 /dev/fuse 这个设备是否存在即可；内核不支持 FUSE 就无法把云盘挂载到本地目录。
  2. 如果打算用非 root 用户运行 CloudDrive2，请按所用发行版的手册安装 fuse3，装好后确认 fusermount3 命令可以运行，并编辑 /etc/fuse.conf，把 user_allow_other 这一行前面的注释符 # 删掉。
  3. 到下载页拿对应 CPU 架构的压缩包。
  4. 打开终端，进入压缩包所在的目录。
  5. 展开压缩包： 
    tar zxvf clouddrive-2-linux-$ARCH-$VERSION.tgz
  6. 进入展开后的目录并运行： 
    ./clouddrive
  7. 可以把 clouddrive 加入开机自启动，或者注册成系统服务。具体做法请参考所用发行版的文档。
Arch Linux
  1. Arch Linux 及其衍生版可以通过 AUR 包 或第三方源安装： 
    yay -Syu clouddrive
  2. 用 systemd 启动 clouddrive 并设为自启： 
    # root 权限
systemctl enable --now clouddrive.service

# 用户权限
systemctl --user enable --now clouddrive.service
  3. 查看 clouddrive 的运行状态： 
    # root 权限
systemctl status clouddrive.service

# 用户权限
systemctl --user status clouddrive.service
  4. 用默认浏览器打开管理界面： 
    # 推荐
xdg-open http://localhost:19798

# IPv4
xdg-open http://127.0.0.1:19798

# IPv6
xdg-open http://[::]:19798
  5. 如果浏览器打开很慢或者卡顿，改用浏览器的无痕模式访问。
  6. 登录后挂载本地磁盘时需要填 UID 和 GID： 
    # 当前用户
id -u
id -g

# 其他用户
id -u username
id -g username
  7. AUR 包预设的本地磁盘挂载位置：/media/clouddrive。
  8. AUR 包预设的 WebDAV 挂载位置：/media/clouddrive-dav，这个功能依赖 davfs2 包。
  9. 把 WebDAV 的用户名和密码写进 /etc/davfs2/secrets，例如： 
    cat << EOF | sudo tee -a /etc/davfs2/secrets
# personal webdav, application password
/media/clouddrive-dav user@email.com  mypassword
EOF
  10. 用 systemd 启动 clouddrive-dav 并设为自启（root 权限）： 
    systemctl enable --now clouddrive-dav.service
  11. 查看 clouddrive-dav 的运行状态（root 权限）： 
    systemctl status clouddrive-dav.service
macOS

用 Homebrew 安装（推荐）

  1. 先确认系统里装好了 Homebrew。
  2. 运行前必须安装 macFUSE，并在「系统设置」里放行它的内核扩展——Apple 芯片的 Mac 还要先进一次恢复模式，完整步骤见给 macFUSE 放行。也可以用 Homebrew 装： 
    brew install --cask macfuse
  3. 安装 CloudDrive2： 
    brew tap cloud-fs/clouddrive2
brew install clouddrive2
  4. 启动 CloudDrive2： 
    brew services start clouddrive2
    启动成功后会自动创建后台服务，下次登录系统时自动运行。
  5. 用浏览器打开 http://localhost:19798 进入管理界面。
  6. 停止 CloudDrive2： 
    brew services stop clouddrive2
  7. 卸载 CloudDrive2： 
    brew services stop clouddrive2
brew uninstall clouddrive2
  8. 升级 CloudDrive2： 
    brew services stop clouddrive2
brew update
brew upgrade clouddrive2
brew services start clouddrive2

手动安装

  1. 运行前必须安装 macFUSE，并按给 macFUSE 放行里的步骤授权。
  2. 到下载页拿对应 CPU 架构的压缩包。
  3. 打开终端，进入压缩包所在的目录。
  4. 展开压缩包： 
    tar zxvf clouddrive-2-macos-$ARCH-$VERSION.tgz
  5. 进入展开后的目录并运行： 
    ./clouddrive
  6. 可以把 clouddrive 加入开机自启动，或者注册成系统服务，具体做法参考系统文档。

这一节讲的是后台服务。Mac 上还有带播放器的 CloudDrive2 应用，App Store 版与官网直接下载版的差异见 macOS 版。

Android
  1. 到下载页的「核心服务」一节拿后缀为 .apk 的安装包，安装后打开即可。它自带 Web 管理界面。
  2. 没有 root 的系统无法把云盘挂载到本地文件系统。 其余功能不受影响，多云盘备份、WebDAV 服务等照常可用；没有 root 时还可以走系统的存储访问框架（SAF），支持 SAF 的第三方应用就能直接读写 CloudDrive2 里的文件。

带播放器的 CloudDrive2 应用是另一个安装包，从 Google Play 或下载页的「应用」一节获取。

Docker、NAS 与群晖 / 威联通

在 NAS 或服务器上用容器跑，镜像是 cloudnas/clouddrive2。宿主机的挂载传播要是共享的，不少系统默认就开着，怎么查、必要时怎么开，连同可直接复制的启动配置，都见 Docker 部署指南。

群晖与威联通的第三方套件在下载页。

群晖用户请留意：File Station 无法在挂载盘里新建或删除文件，这是群晖侧的已知问题，绕开办法见常见问题。

飞牛 fnOS 请用原生套件，不要用 Docker

容器里做 FUSE 挂载会撞上 fnOS 的命名空间限制，报 mount syscall failed in pid 1 namespace。我们提供了原生的 fpk 套件，装上就没有这个问题，在下载页。

第二步

连上第一个云盘

注册、登录、添加云存储，三步。三步都在浏览器里的管理界面完成，应用里的流程也一样。

  1. 注册

    第一次运行 CloudDrive2 后，点击右上角的「注册」按钮，填入邮箱地址和密码。系统会往这个邮箱发一封验证邮件，按邮件里的提示完成验证；验证成功后会自动跳转到登录页面。

  2. 登录

    点击右上角的「登录」按钮，填入同一组邮箱地址和密码。账号已经通过验证的话，就会跳转到 CloudDrive2 的主页。

  3. 添加云存储

    进「云存储」页，点「添加云存储」，在列表里选你的服务商，按提示扫码或填账号信息。验证通过后，这个云盘就会出现在「我的文件」里，和其他云盘并排。

免费账号可以连 2 个云盘、建 1 个本地挂载；核心会员不限数量。各档的区别见会员与价格。

第三步（可选）

把云盘挂载成本地磁盘

挂载之后，云盘在资源管理器、访达和命令行里就是一块普通磁盘，任何软件都能直接打开里面的文件，不用先下载。这是 CloudDrive2 和网盘客户端最不一样的地方。

建一个挂载点

  1. 进「挂载点」页，点「添加挂载点」。
  2. 挂载名称：随便起，显示用。
  3. 源目录：要挂出去的那个目录。可以是某个云盘的根目录，也可以是它下面的任意一层；填 / 就是把所有已连接的云盘一起挂出去。
  4. 挂载点：Windows 上是一个盘符，Linux 与 macOS 上是一个空目录。
  5. 选项：勾「只读」可以防误删误改；勾「启动时自动挂载」让它跟着服务一起起来。
  6. Linux 与 macOS 还有「高级设置」，可以指定 UID、GID 和权限（默认 0755），决定挂载出来的文件属于哪个用户。

每个系统各需要什么

系统 前置组件 挂载点填什么
Windows WinFSP，挂载点页面上有一键安装按钮，装一次即可 盘符，例如 X:
macOS macFUSE 与内核扩展放行；Apple 芯片的 Mac 要先进恢复模式 一个空目录

Windows 上挂载出来的盘还分「本地」和「网络」两种类型，有些软件只认其中一种，挂不上或者软件看不见时可以换一种试试。

Docker 里挂载看不见？

容器内挂载成功、宿主机上却没有，几乎都是共享挂载传播没配。启动参数要带 --cap-add SYS_ADMIN --device /dev/fuse --security-opt apparmor:unconfined（或者直接 --privileged），挂载目录映射要写成 :shared。完整配置见 Docker 部署指南。

本地挂载的完整说明

客户端

在手机、电视和头显上用

应用不是上面那台服务器的遥控器，它自带完整的核心：装上、登录、添加云盘就能用，不需要另外架服务器。当然，如果你已经有一台在跑，也可以让应用连过去。

  • 独立使用

    在应用里注册或登录同一个 CloudDrive 账号，然后添加云存储——步骤和浏览器里一模一样。手机上没有服务器也照样能浏览、播放、备份。

  • 连到已有的服务器

    家里 NAS 上已经跑着 CloudDrive2，就在那台上建一个 API 令牌，在应用里用地址加令牌把它添加进来。之后离线下载、搜索、跨云复制这些都能在应用里直接用。

  • 会员与 App 专业版

    核心会员和 App 专业版都记在 CloudDrive 账号上，不绑设备也不绑商店。在哪个平台买的，换个平台登录同一账号照样是解锁状态。

日常使用

连上之后还会用到的

文件管理

「我的文件」把所有已连接的云盘并排放在一起，上传、下载、重命名、移动、删除、新建文件夹都是跨云盘的操作，不只是在单个云盘里。列表、网格和瀑布流三种视图，排序、搜索、多选都有。

挂载成本地磁盘之后，这些文件在资源管理器、访达或任何软件里都能像本地文件一样操作。

删除操作不可撤销

在 CloudDrive2 里删除文件，删的就是云存储上的真实文件。一旦删除，可能无法恢复，请先确认再动手。

跨云盘复制

像在同一个云盘里那样，把文件从一个云盘拖到另一个。先从源云盘取哈希：目标云盘用的是同一套哈希算法、并且命中了，就是真·秒传——服务端直接建一条指向已有数据的记录，数据根本不搬；算法不同或者没命中，就在两朵云之间边下边传，不落地到本地磁盘，速度受你的带宽限制。

操作在「我的文件」里：勾中要复制的文件或文件夹，点「移动/复制到...」，在目录树里选好目标，点「复制」。任务在后台跑，不用守着；进度到「任务」页看，「复制任务」和「上传任务」两个标签下都找得到。

跨云盘快速复制是核心会员功能。慢的那一种情况不是出了问题，是目标云盘那边没有可以命中的现成数据。

在「云存储」页点「添加云存储」，在「本地存储」里选「本地文件夹」，就能把机器上的一个目录加进来当复制的源或目标。只要有一端是本地文件夹，免费账号也能复制——把云盘上的东西拿下来，或者把本地的东西传上去，都不需要会员。

目标是本地文件夹时，任务会出现在「上传任务」里。方向没搞反：CloudDrive2 把复制统一成读源端、写目标端的一条流水线，写的那一半一律叫上传。

跨云盘复制的完整说明

备份
  1. 进「备份」页，点「添加备份」，按向导选源目录和一个或多个目标目录。本地文件夹和云盘目录都可以当源，也都可以当目标。
  2. 设置文件过滤规则（按扩展名或文件名，可以分别对文件和文件夹生效）和完成规则（例如上传完成后删除源文件）。
  3. 备份靠文件系统的实时监控工作：源目录里的改动一发生就同步过去。此外还可以配完整扫描的计划，定期对一遍。
在网盘官方 App 里改的东西，实时备份不会触发

实时监控只看得到 CloudDrive2 里发生的改动。云服务商不提供文件变更通知，所以备份源是网盘目录时，你在网盘自己的 App 或网页上传、删除、改名的文件，CloudDrive2 无从知晓。

要让它发现：在「我的文件」里刷新一次那个网盘目录。开启「目录缓存持久化」后，刷新会拿新读到的目录内容和已存的缓存比对，比出来的差异会照常触发实时增量备份。或者等计划中的完整扫描来对账。

删除为什么没跟着同步

删除有两条路径。实时监控抓到的删除事件是确凿的，会按删除规则同步到目标端；而完整扫描只能看出「目标端有、源端没有」，这未必是删除，也可能是文件被移到了别处，照着删有风险。所以要不要据此删除，交由你在完整扫描规则里的「同步删除」选项自行开启。

源目录本身就是挂载的网盘时，实时删除事件不一定触发，这个选项尤其有用。

备份全量扫描很吃资源。「备份资源限制」里可以设最大并发扫描数（默认 1）和上传队列的上下限，避免扫大目录时堆出一大堆上传任务。

加密文件夹

在任意云盘目录上右键选「创建加密文件夹」，设一个密码。之后往里面放的文件，文件名和内容都在本地加密后再上传——云端存的是密文，服务商看不到原文。解锁之后，读写和普通文件夹没有区别。

不用的时候点「锁定」，下次访问要重新输密码。创建时可以勾「保存密码」，重启后不必再输。

密码无法找回

加密文件夹的密码既不能改也不能恢复。忘记密码，文件夹里的内容就永久打不开了——我们也没有办法。

加密文件系统的完整说明

WebDAV 服务

CloudDrive2 会把所有已连接的云盘再以一个 WebDAV 服务对外提供，任何支持 WebDAV 的软件都能连上来。

  • 服务器地址：http://<ip>:19798/dav
  • 用户名：登录 CloudDrive2 的邮箱；也可以只填邮箱的用户名部分，即 @ 之前的那一段。
  • 密码：登录 CloudDrive2 的密码。

核心会员还可以在「WebDAV」页建独立的 WebDAV 用户，各自限定能看到哪个目录、能不能写，不必把主账号密码交出去。

WebDAV 的完整说明

API 令牌

第三方应用可以用 API 令牌访问 CloudDrive2，不必知道你的账号密码。进「API 令牌」页点「创建令牌」，可以限定它能访问的根目录、有效期，以及每一项操作的权限——文件读取、写入、修改、系统操作、云存储操作、账号操作，每一大项下面还能逐条勾。

给 Emby / Jellyfin 插件用的令牌要多勾两项

新建令牌时「推送消息」与「获取挂载点」默认没有勾选，必须手动勾上。少了它们，插件能连上、状态也显示正常，但媒体库永远不会自动更新。

Emby / Jellyfin 伴侣插件

离线下载

在支持的云盘目录里点「离线下载」，把磁力链接或 .torrent 文件交给云盘那边去下，下完直接落在云盘里，本地不占带宽也不占空间。.torrent 可以直接拖进来，会被解析成磁力链接后添加。

115 网盘还有一个离线下载管理窗口，可以复制链接、删除任务、重新开始，或者按状态批量清理。

账号

账号与安全

存在云端的云存储账号信息是用你的密码加密的，我们不保存你的密码。这一节的几件事都跟这条有关。

忘记密码

在登录界面点「重置」按钮，按提示重置——系统会往你的邮箱发一个重置代码。

重置会清空云端账号信息

重置会清空你保存在云端的云存储账号信息并重置密码，重置后需要重新添加云存储。会员计划不受影响。

修改邮箱与密码

在「个人资料」页改。改邮箱要先收一封验证码邮件，验证通过才生效。改密码不会影响已经添加的云存储。

通过迅雷或合作伙伴设备直接登录的账号，只能改邮箱和密码中系统允许的那部分，页面上会写清楚。

两步验证

在「个人资料」页开启。用任意 TOTP 验证器应用扫码绑定，绑定成功后会给你一组恢复代码——请单独存好，验证器丢了就靠它登录。

验证器和恢复代码都没了怎么办

在登录界面点「无法使用验证器？通过邮箱禁用两步验证」，系统会往账号邮箱发一个验证码。用这个验证码加账号密码就能关掉两步验证，之后用邮箱密码正常登录。验证码 30 分钟内有效。

设备解绑

合作伙伴设备自动注册的账号，在改过邮箱和密码之后可以与原设备解绑。设备丢了或者卖掉了，解绑一次可以避免账号泄露。

离线的设备上可能还留着已保存的凭据，解绑之后建议再改一次密码，把那条路彻底断掉。

排错

常见问题

下面这些是被问得最多的几个，答案来自我们在 GitHub issues 和支持邮箱里的回复。

套了反向代理之后，界面一直卡在「连接中…」

根因是反向代理把 PushMessage 这条 gRPC-Web 长连接给缓冲了，响应头一直不下发，前端就一直等；仪表盘上的任务数也跟着不刷新。在 nginx 里为 CloudDrive2 的转发关掉缓冲、放大读超时即可：

location / {
    proxy_pass http://127.0.0.1:19798;   # 改成你的 CD2 HTTP 端口
    proxy_http_version 1.1;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;

    # 关键：流式 gRPC-Web 必须关闭缓冲
    proxy_buffering off;
    proxy_request_buffering off;
    chunked_transfer_encoding on;
    proxy_set_header Connection "";

    # PushMessage 是长连接，读超时要放大
    proxy_read_timeout 3600s;
    proxy_send_timeout 3600s;
}
macOS 启动报 libfuse.2.dylib 缺失

这是没有安装 macFUSE。挂载功能依赖它提供 libfuse.2.dylib。到 macfuse.github.io 下载安装，再按给 macFUSE 放行里的步骤在系统设置里允许它的内核扩展——Apple 芯片的 Mac 还要进一次恢复模式。

添加 Google Drive 时报「此应用已被阻止」

用你自己的 Google OAuth 凭据就不会被拦：到 Google Cloud Console 新建一个项目，启用 Google Drive API，配置 OAuth 同意屏幕并把自己加为测试用户，然后创建 OAuth 客户端 ID，拿到 client_id 与 client_secret；在 CloudDrive2 里添加 Google Drive 时填进去即可。这样授权走的是你自己的应用。

115 扫码成功，但云盘不显示

旧的「115」私有接口已经下线，扫码会成功但连不上。请改用 115open：先移除当前的 115，再添加 115open，然后把它重命名回原来的名字——挂载路径就不会变，已配置的挂载点和备份都不用改。

如果是连不上、报网络错误，那多半是到 115 或天翼登录接口的网络不通，先查 DNS 和代理再重试。

115 突然变慢、报错，或者容量显示为 0

多数时候这是 115 那边的临时限制，不是 CloudDrive2 出了问题。短时间访问太频繁会触发 115 的风控，一般半小时左右自动恢复；下载被卡在几 MB/s 通常是 115 对账号的临时限速，24 小时内恢复。晚间高峰慢、白天正常，也是 115 的策略，改什么设置都没用。

能做的预防：保持默认设置就好，不必调大并发；同一个 115 账号尽量只在一台机器的 CloudDrive2 上用，多台机器同时访问同一账号更容易触发风控。

123 云盘加不上、授权失败

123 云盘调整过接口地址，老版本的 CloudDrive2 连的还是旧地址。升级到最新版，再重新添加 123 云盘即可。

想加同一个网盘的第二个账号，登录页却直接进了第一个

那是浏览器里还留着第一个账号在网盘官网的登录状态。用无痕（隐私）窗口打开 CloudDrive2 再添加，或者先去网盘官网退出登录，就能登第二个账号了。两个百度网盘、两个 115 都是这么加。

日志里刷 too many requests

阿里云盘等服务商会对 API 调用限流，超了就返回 too many requests。CloudDrive2 会自动等待并重试直到成功，这类日志不需要处理。它也不会打断挂载盘上的写入：写入先落到本地临时文件，上传在后台异步进行。

Windows 上打不开 19798

按这个顺序查，多数问题在第一步就露馅了。

  1. 服务在不在跑。按 Win+R 打开 services.msc，找 CloudDrive2 Service（服务名 CloudDrive2）。状态应该是「正在运行」，启动类型应该是「自动」。停着就右键启动它；启动类型被改成「手动」或「禁用」的，右键 →「属性」改回「自动」，否则下次开机它不会自己起来。命令行同样能看： 
    sc query CloudDrive2
  2. 服务在跑，但别的机器连不上。那是 Windows 防火墙没放行端口——核心服务 19798，开了 HTTPS 再加 19799。本机用 http://localhost:19798 能开、别的机器打不开，基本就是这一条。
  3. 服务起不来，或者刚起来就停。多半是被杀毒软件拦了。把 CloudDrive2 的安装目录和 WinFSP 一起加进白名单再试。
杀毒软件报安装包有毒

这是误报。安装包经过代码签名，被检出的 is-XXXX.tmp 只是 Inno Setup 安装器解包时的临时文件，被启发式引擎误判。可以把安装目录和安装包加进杀软白名单，并向厂商提交误报反馈。

装完之后也可能被拦：服务起不来、挂载盘出不来，或者应用被直接关掉。签名齐全也挡不住启发式引擎，把 CloudDrive2 的安装目录和 WinFSP 一并加进白名单即可。

添加云盘、检查更新时报网络错误（dns error、connect error）

错误里带 dns error、connect error 的，问题都出在运行 CloudDrive2 的那台机器的网络上：查它的 DNS 和代理设置，Docker 部署再查容器网络能不能出外网。管理页面往往是在别的设备上打开的，浏览器能上网不代表跑 CloudDrive2 的机器能上网——测试要在跑服务的那台机器或容器里做，比如 curl 一下报错信息里的那个地址。

Docker 里的 Emby / Jellyfin 只能看到挂载目录，看不到里面的文件

这是 Docker 的挂载传播（mount propagation）问题：CloudDrive2 的 FUSE 挂载发生在容器启动之后，默认的传播模式让 Emby 容器看不到后来出现的挂载。给 Emby / Jellyfin 容器的目录映射加上 :rslave 即可，例如 -v /mnt:/mnt:rslave，重建容器后生效。

开了 115 直链，流量却还是走服务器

直链是两个 CloudDrive 之间的机制：远程的 CloudDrive 客户端向服务端请求直接下载地址，数据才不经过服务器。用浏览器打开网页界面访问文件不走直链，流量仍然经过运行 CloudDrive2 的机器。

iPhone / iPad 应用的 WebDAV 连不上

先查端口：手机与平板应用内置服务的端口是 29798，不是核心服务的 19798。在播放器里填 WebDAV 地址时，用 http://<设备 IP>:29798 再试。

群晖 File Station 里无法新建、重命名或删除挂载盘中的文件

群晖自带的 File Station 不支持在 FUSE 挂载的文件系统上做写操作，这是群晖侧的已知问题，不少用户都碰到过。表现是挂载点进得去、文件看得到也放得了，但新建文件夹、重命名、删除、移动和上传全部失败。

挂载本身没问题：同一个挂载点，用 SSH 或者别的文件管理器读写都正常。

绕开的办法有两个：在 File Station 里改用 CloudDrive2 的 WebDAV 服务连接，不走 FUSE 挂载路径；或者在群晖上换用第三方的文件管理器。同时也建议向群晖反馈这个问题——反馈的人多了才有希望修。

挂载报 IO Error：mount point is not empty

挂载点目录必须是空的。这个错误常见于重启之后：某个也在用这个路径的程序——Emby、下载工具、备份脚本都有可能——比 CloudDrive2 服务先启动，在目录真正被挂载之前往里写了东西，CloudDrive2 就拒绝在非空目录上挂载。

处理：先停掉往里写的程序，把挂载点目录里遗留的文件清走——它们在本地磁盘上，不在云盘里，清之前先看看有没有要保留的——然后重新挂载。要断根，就让依赖这个路径的程序晚于 CloudDrive2 启动：把它的服务设成依赖 CloudDrive2 服务，或者给它加一个延迟启动。

Windows 7 上装不了 / 登录不了

Windows 7 已停止支持，其系统自带的 TLS 和运行库无法满足当前版本对安全连接和依赖的要求。建议在 Windows 10 / 11 上使用；如果必须在旧设备上跑，可以考虑改用 Linux 或 Docker 版本。
