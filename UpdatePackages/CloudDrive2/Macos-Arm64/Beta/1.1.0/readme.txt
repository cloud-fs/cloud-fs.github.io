CloudDrive2 Core V1.1.0(Web3.1.0)

1. 备份新增双向同步。 以前备份只能从源文件夹复制到目标文件夹，目标文件夹里的改动不会回到源文件夹，还可能在下次扫描时被覆盖；现在把"备份模式"设为"双向同步"后，在任何一个文件夹中添加、修改、重命名或删除文件，其他文件夹都会跟着变，本地文件夹和云端文件夹都可以参与。同一个文件在两处都被修改时默认保留两个版本（其中一个以"冲突副本"命名并同步到所有位置），被替换和被删除的文件保存在原位置旁边的 .clfs_history 文件夹中。删除默认不同步，需要打开"同步删除"；即使打开，一次大量的删除或修改也会暂停下来等待确认，可以选择执行或从其他位置恢复。云端文件夹按扫描计划检查，在网盘官方客户端或网页版中所做的更改会在下次扫描后同步，在 CloudDrive 中浏览到该文件夹时也会立即同步，建议有云端文件夹参与时把扫描间隔设为 15 分钟或更长。双向同步默认关闭，升级后已有备份仍按单向备份运行，行为和 1.0.20 一样。详细说明见 https://www.clouddrive2.com/two-way-sync.html

2. 账号云端同步可以随时开关。 "与云端同步"以前只能在登录时决定，登录后再打开可能会用本机的账号列表覆盖云端（其他设备上添加的账号因此丢失），或者反过来被云端覆盖。现在开关之前会先显示云端和本机的账号逐个对比（一致、不同、只在本机有、只在云端有），开启时可以选择以云端为准（默认）或以本机为准；从查看对比到点击确认之间云端如果被其他设备改过，操作会中止并提示重新确认，不会在不知情的情况下覆盖。关闭时可以选择是否同时清除服务器上的副本，标记为"不同步到云端"的账号始终留在本机。115 网盘的令牌改为按账号处理，同步开启期间添加的账号在关闭同步后仍可正常使用

3. 添加 Google Drive 时可以使用自己的 Google 客户端。 CloudDrive 自带的 Google 客户端没有通过 Google 的审核，只有加入测试用户名单的 Google 账号才能用它登录。现在添加 Google Drive 默认使用你自己在 Google Cloud 中创建的"桌面应用"类型的 OAuth 客户端（免费，只需创建一次）：选择创建客户端时下载的 client_secret_….json 文件，客户端 ID 和密钥会自动填入，这个文件可以从本机选择，也可以从已经添加到 CloudDrive 的云盘中选择；然后在浏览器中登录 Google 并允许访问，即可完成添加。浏览器和 CloudDrive 不在同一台设备上时，把登录后浏览器地址栏中以 http://127.0.0.1 开头的地址复制回来即可完成。原来的两种方式（CloudDrive 的客户端、刷新令牌）仍可选择；使用刷新令牌添加时，设置的代理从第一次请求起就生效，令牌错误或没有启用 Google Drive API 时会提示原因，不再添加一个无法使用的账号。创建客户端的步骤见 https://www.clouddrive2.com/google-drive-client.html

4. 光鸭云盘支持上传和文件管理。 新增上传（支持断点续传，文件已在服务器上时走秒传）、新建文件夹、重命名、移动，并显示网盘的容量和已用空间。开放平台目前还没有提供删除和复制接口，这两个操作暂时不可用；上传和写入需要开放平台为应用开通相应权限，账号也需要是有效会员

5. WebDAV 页面显示服务器的访问地址(#581)。 页面上以前显示的是 localhost 或 [server-ip]，需要自己换成服务器的地址；现在直接列出服务器在局域网中的 IP 地址和端口（例如 http://192.168.1.10:19798/dav），并说明从外网访问、使用 HTTPS 或反向代理、以及 CloudDrive 在 Docker 容器中运行时应该如何访问。开启匿名访问后，用户名留空和填写 anonymous 效果相同，页面上也说明了匿名访问的登录方式

6. 修复 WebDAV 服务中移动或复制到已有文件时失败的问题(#575)。 一些 WebDAV 客户端保存文件时，先上传一个临时文件，再把它移动到原文件的位置替换原文件；目标文件已经存在时，CloudDrive 的 WebDAV 服务返回 405 错误，所以只有第一次保存能成功。现在移动到已有文件时会替换该文件，替换完成之前原文件一直保留，替换失败时原文件不受影响。复制到已有文件时以前返回成功但实际没有复制，现在同样会替换；复制到同一文件夹下的另一个名字以前会被拒绝，现在可以完成。客户端要求不覆盖时，仍然不会替换已有文件

7. SFTP、WebDAV、SMB 上传不再留下半截文件。 上传时先写入一个临时文件名，完成后再改成正式名字，中途断开或取消不会再留下一个大小不对的同名文件覆盖掉原来的文件；WebDAV 上传失败时也会明确报错，不再被忽略

8. 修复 123 云盘显示的容量不正确的问题。 123 云盘现在把空间分为专业空间和标准空间，以前只统计了其中一部分，总容量里还加上了临时空间，所以和 123 云盘官方页面显示的不一致，例如 1 TB 专业空间加 42.66 TB 标准空间的账号显示为 62.6 TB。现在总容量和已用空间与官方页面一致

9. 修复迅雷云盘上传任务数一直被占用的问题。 迅雷为每个上传建立一条任务记录，并按"正在进行的上传"计数，直到上传完成或任务被删除；CloudDrive 之前不会删除被放弃的任务（失败重试、取消传输、上传会话丢失都会各留下一条），积累多了，迅雷客户端会提示"同时可进行任务数受限"。现在被放弃的任务会及时删除

10. 网页版的无障碍改进。 文件夹选择框中的项目可以用键盘选择；全屏查看图片或视频时，用键盘或读屏软件移到控制按钮上，隐藏的控制栏会重新显示；备份页面的按钮、标签页和菜单可以被读屏软件正确读出

11. 飞牛 fnOS：修复安装时修改了端口后，桌面图标仍然打开默认端口 19798 的问题。 安装向导中填写的 HTTP 端口会写入 CloudDrive 的配置，但桌面图标固定打开 19798，因此无法打开 CloudDrive。现在桌面图标打开安装时填写的端口。保留旧数据重新安装时，安装向导中填写的端口会替换旧配置中的端口，其他设置保持不变。安装后可以在应用中心打开本应用的设置，修改 HTTP 和 HTTPS 端口，保存后 CloudDrive 会重新启动，桌面图标也会使用新端口；如果在 CloudDrive 的网页中修改过端口，在这里保存一次即可更新桌面图标

说明：

双向同步是新功能，建议先用不重要的文件夹试用一段时间，确认符合预期后再用于重要数据。

如果需要退回 1.0.20，请先停用设为双向同步的备份：配置文件可以被旧版本读取，但旧版本不认识双向同步，会把这些备份当作单向备份运行，只把源文件夹的内容复制到目标文件夹。

已知问题：单向备份中同时打开"从目标同步删除"、并把删除规则设为"移到历史文件夹"时，目标文件夹中的 .clfs_history 文件夹本身会被当成多余内容再次移入历史文件夹，每扫描一次多嵌套一层（1.0.20 同样存在）。修复之前请不要同时使用这两个选项。
