CloudDrive2 Core V1.1.0-beta(Web3.1.0-beta)

1. 备份新增双向同步。 以前备份只能从源文件夹复制到目标文件夹，目标文件夹里的改动不会回到源文件夹，还可能在下次扫描时被覆盖；现在把"备份模式"设为"双向同步"后，在任何一个文件夹中添加、修改、重命名或删除文件，其他文件夹都会跟着变，本地文件夹和云端文件夹都可以参与。同一个文件在两处都被修改时默认保留两个版本（其中一个以"冲突副本"命名并同步到所有位置），被替换和被删除的文件保存在原位置旁边的 .clfs_history 文件夹中。删除默认不同步，需要打开"同步删除"；即使打开，一次大量的删除或修改也会暂停下来等待确认，可以选择执行或从其他位置恢复。云端文件夹按扫描计划检查，在网盘官方客户端或网页版中所做的更改会在下次扫描后同步，在 CloudDrive 中浏览到该文件夹时也会立即同步，建议有云端文件夹参与时把扫描间隔设为 15 分钟或更长。双向同步默认关闭，升级后已有备份仍按单向备份运行，行为和 1.0.20 一样。详细说明见 https://www.clouddrive2.com/two-way-sync.html

2. 账号云端同步可以随时开关。 "与云端同步"以前只能在登录时决定，登录后再打开可能会用本机的账号列表覆盖云端（其他设备上添加的账号因此丢失），或者反过来被云端覆盖。现在开关之前会先显示云端和本机的账号逐个对比（一致、不同、只在本机有、只在云端有），开启时可以选择以云端为准（默认）或以本机为准；从查看对比到点击确认之间云端如果被其他设备改过，操作会中止并提示重新确认，不会在不知情的情况下覆盖。关闭时可以选择是否同时清除服务器上的副本，标记为"不同步到云端"的账号始终留在本机。115 网盘的令牌改为按账号处理，同步开启期间添加的账号在关闭同步后仍可正常使用

3. 光鸭云盘支持上传和文件管理。 新增上传（支持断点续传，文件已在服务器上时走秒传）、新建文件夹、重命名、移动，并显示网盘的容量和已用空间。开放平台目前还没有提供删除和复制接口，这两个操作暂时不可用；上传和写入需要开放平台为应用开通相应权限，账号也需要是有效会员

4. SFTP、WebDAV、SMB 上传不再留下半截文件。 上传时先写入一个临时文件名，完成后再改成正式名字，中途断开或取消不会再留下一个大小不对的同名文件覆盖掉原来的文件；WebDAV 上传失败时也会明确报错，不再被忽略

5. 修复备份过滤规则在某些情况下让整个备份失效的问题(#490)。 作用于文件夹的正则或扩展名规则以前是拿整条路径的每一段去匹配，包括网盘名和根文件夹名：白名单里没写源文件夹的名字，整个备份就什么都不备份；写了则等于全部放行。现在规则按相对于备份文件夹的路径判断，根文件夹本身不会被排除

6. 修复迅雷云盘上传任务数一直被占用的问题。 迅雷为每个上传建立一条任务记录，并按"正在进行的上传"计数，直到上传完成或任务被删除；CloudDrive 之前不会删除被放弃的任务（失败重试、取消传输、上传会话丢失都会各留下一条），积累多了，迅雷客户端会提示"同时可进行任务数受限"。现在被放弃的任务会及时删除

测试版说明：

双向同步是全新功能，建议先用不重要的文件夹试用一段时间，确认符合预期后再用于重要数据。

如果需要退回 1.0.20，请先停用设为双向同步的备份：配置文件可以被旧版本读取，但旧版本不认识双向同步，会把这些备份当作单向备份运行，只把源文件夹的内容复制到目标文件夹。

已知问题：单向备份中同时打开"从目标同步删除"、并把删除规则设为"移到历史文件夹"时，目标文件夹中的 .clfs_history 文件夹本身会被当成多余内容再次移入历史文件夹，每扫描一次多嵌套一层（1.0.20 同样存在）。修复之前请不要同时使用这两个选项。
