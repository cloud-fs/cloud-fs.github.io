系统要求

macOS 12 或更高版本，Apple 芯片与 Intel 通用。这一版由 Apple 公证，首次打开不会有安全警告，也不在沙盒里运行——本地挂载（需要 macFUSE）、蓝光 BD-J 光碟菜单和 USB 原生 DSD 只在这一版里有，两版差异见 macOS 版。

Android 7.0 或更高版本，同一个包适配手机、平板与 Android TV。通用 APK 覆盖 arm64-v8a 与 armeabi-v7a（32 位 ARM），不含 x86_64。

iPhone、iPad、Apple TV、Vision Pro 和 Meta Quest 只能从各自的商店安装，见上方。Windows 上现在可以先装核心服务，用浏览器管理云盘。

插件

Emby / Jellyfin 伴侣插件

装在媒体服务器那一侧，让 Emby 或 Jellyfin 与同一台主机上的 CloudDrive2 协同工作。一套源码，两个版本。

  • 媒体库实时更新，实时监控可以全关

    插件订阅 CloudDrive2 的文件变更通知，把每条变化直接交给服务器的定向刷新入口。刮削器（tinyMediaManager、MoviePilot、MDCx 等）在挂载目录里改完，影片自动出现在库里——不必开「实时监控」，也就没有开机时的递归遍历和云端列目录风暴，更不用靠整库扫描，而整库扫描正是触发网盘风控的主要原因。

  • 按播放行为预热

    起播时预热文件头尾（moov / EBML 头与 MKV cues），接近片尾时预热同一目录里的下一个文件，停止播放时立刻收回读取器。所有客户端一并受益，不限于 CloudDrive2 App。

  • 免配置路径映射

    直连播放要知道服务器上的媒体目录对应本机哪个网盘目录，过去得手写规则。插件把挂载点和网盘账号身份暴露出来，App 登录后自己算——按账号身份匹配，不按文件夹名，因为同一个 115 账号两端常常叫不同的名字。

下载

  • Emby 版最新发布
  • Jellyfin 版最新发布

Jellyfin 把 DLL、meta.json 与 thumb.png 一起放进插件目录下的 CloudDrive 子文件夹；Emby 只需把 DLL 放进插件目录，不要子文件夹。装在容器里更新 DLL 后请重启容器，服务器自带的「重启」按钮不够。完整的安装与配置说明见 插件仓库。

环境要求

服务器最低版本：Emby 4.8.0.80 或 Jellyfin 10.11。已在 Emby 4.9.5 与 Jellyfin 10.11.11 上验证。

前两项功能是纯服务端的，装上插件、填好 CloudDrive2 地址就能用，不需要安装 CloudDrive2 App。其中媒体库实时更新依赖文件变更通知，属于会员（Pro）功能。免配置路径映射则需要 CloudDrive2 App 1.0.14 或更高版本。

插件在 CloudDrive2 里用 API 令牌连接。新建令牌时「推送消息」与「获取挂载点」默认没有勾选，必须手动勾上——少了它们，插件能连上、状态也正常，但媒体库永远不会自动更新。插件不写入、不删除、不修改任何文件。

1.0.13(Web3.0.13)
  1. 多网盘备份增加全量扫描资源占用控制功能：
    1. 默认并发备份扫描数为1，可以在备份页面修改最大并发数，超过的备份全量扫描会排队等待

  4. 修复Web界面实时显示的任务数可能不准确的问题

1.0.7(Web3.0.7)

⚠️ 重要安全提示（Windows 用户必读）

本版本将 WinFSP 升级至 2026 beta1，以修复旧版本 WinFSP 中发现的安全漏洞 CVE-2026-3006。

  • 请务必下载完整安装包重新运行安装程序，并按安装向导提示重启系统。
  • 请勿使用应用内 OTA 升级：OTA 仅替换 CloudDrive2 程序文件，不会重新安装 WinFSP 驱动，将无法获得本次安全修复。
  1. 115网盘配置界面最大下载线程数限制为2，设置的值不能超过2
  2. 115网盘配置界面增加每秒最大请求数限制，最大不能超过5.0
  3. SMB/SFTP/FTP新增支持获取磁盘空间大小（仅部分 FTP 服务端支持，目前已知 Pure-FTPd 与启用 mod_facts 的 ProFTPD 可正确返回，其它服务端将回退为占位值。受协议限制，AVBL 只返回可用字节数，因此总容量与可用相同、已用显示为 0）
  4. 改进smb服务器和共享发现算法，适应更多场景
  5. 文件重命名冲突处理方式改进：
    • 核心层(webdav/http/clouddrive共享等)的重命名冲突从原来的直接覆盖旧文件（遵循POSIX重命名行为）改为返回重命名失败
    • Linux和macOS保持原来的遵循Unix重命名覆盖语义-先删除旧文件再重命名，若旧文件为非空目录则返回错误ENOTEMPTY，符合POSIX rename(2)行为
    • Windows由原来的遵循POSIX行为改为循序Win32 MoveFile默认行为，即重命名冲突时返回ERROR_ALREAD_EXISTS错误，资源管理器会弹出"目标已存在"提示
  6. 通过迅雷直接登录的帐号和通过合作伙伴设备直接登录的帐号，在个人资料页屏蔽修改密码选项，只保留修改邮箱和密码选项
  7. 修复web界面复制到剪贴板按钮在非安全上下文(访问cd2的url为http://且非localhost)下工作不正常的问题
  8. 其它性能改进和bug修复
