远程文件上传（客户端开发者指南）

本指南说明如何实现一个将文件上传到远程 CloudDrive gRPC 服务器的客户端。重点介绍客户端工作流程、进度报告、哈希计算（包括可选的 MD5 块哈希）、取消操作以及可靠性行为。

RPC 和消息概览

  • StartRemoteUpload（一元调用）
    • 请求：StartRemoteUploadRequest
    • 响应：RemoteUploadStarted
  • RemoteUploadChannel（服务器端流式；每个客户端会话使用一个长连接通道）
    • 请求：RemoteUploadChannelRequest
    • 响应：RemoteUploadChannelReply
      • 字段：upload_id
      • oneof request
        • read_data: RemoteReadDataRequest
        • hash_data: RemoteHashDataRequest
        • status_changed: RemoteUploadStatusChanged
  • RemoteReadData（一元调用）
    • 请求：RemoteReadDataUpload
    • 响应：RemoteReadDataReply
  • RemoteHashProgress（一元调用）— 用于进度更新和哈希请求的完成
    • 请求：RemoteHashProgressUpload
    • 响应：RemoteHashProgressReply
  • RemoteUploadControl（一元调用）
    • 请求：RemoteUploadControlRequest（oneof: cancel、pause、resume）
    • 响应：google.protobuf.Empty（错误通过 RPC 状态返回）
关键协议说明：
  • 所有操作都通过服务器提供的 upload_id（从 StartRemoteUpload 返回）进行索引。
  • RemoteUploadChannel 请求必须包含一个稳定的 device_id，用于唯一标识客户端设备；在重启后重用它，以便服务器可以替换通道并重放待处理的工作。
  • file_path 仅在 StartRemoteUpload 中提供；后续消息通过 upload_id 索引。不使用 cloudName/cloudAccountId。
  • 服务器的哈希请求可能包含可选的 block_size（仅 MD5）以请求每块 MD5。
  • 最终的哈希值（以及任何块哈希）必须通过 RemoteHashProgress 传递。
  • 客户端控制（暂停/恢复/取消）通过 RemoteUploadControl 发送。状态变化通过流上的 RemoteUploadStatusChanged 观察；控制 RPC 成功时返回 Empty，不携带状态。

消息契约（关键字段）

StartRemoteUploadRequest

  • file_path: string — 服务器上的目标路径
  • file_size: uint64 — 总字节数
  • known_hashes: map<uint32, string> — 可选的预计算文件哈希；键为 CloudDriveFile.HashType 数值（1=MD5, 2=SHA1, 3=PIKPAK_SHA1）

RemoteUploadChannelRequest

  • device_id: string — 客户端设备的稳定标识符。在进程重启时重用相同的值（例如，CloudFS 的 SELF_GENERATE_MACHINE_ID）。

RemoteUploadChannelReply

  • upload_id: string
  • oneof request
    • RemoteReadDataRequest
      • offset: uint64
      • length: uint64
      • lazy_read: bool
    • RemoteHashDataRequest
      • hash_type: HashType（例如 MD5、SHA1、PIKPAK_SHA1）
      • block_size: uint32（可选；仅 MD5；0 或未设置表示无块哈希）
    • RemoteUploadStatusChanged
      • status: UploadFileInfo.Status（例如 WaitforPreprocessing、Preprocessing、Transfer、Pause、Cancelled、Finish、Skipped、Inqueue、Ignored、Error、FatalError）
      • error_message: string（当状态指示错误时设置）

RemoteReadDataUpload

  • upload_id: string
  • offset: uint64
  • length: uint64
  • lazy_read: bool
  • data: bytes
  • is_last_chunk: bool

RemoteHashProgressUpload

  • upload_id: string
  • bytes_hashed: uint64 — 累计进度
  • total_bytes: uint64 — 通常是文件大小
  • hash_type: HashType
  • hash_value: string（可选；仅在最终进度消息中存在）
  • block_hashes: repeated string（可选；仅 MD5；仅当 block_size > 0 时在最终进度消息中存在）

端到端客户端工作流程

  1. 启动上传

    使用 file_path 和 file_size 调用 StartRemoteUpload。使用返回的 upload_id 进行所有后续 RPC。

  2. 打开全局通道

    每个客户端会话调用一次 RemoteUploadChannel 并保持打开。每次连接时提供相同的 device_id（即使在重启进程后）。服务器使用 device_id 为该设备切换到最新的流，并自动将任何未完成的读取/哈希请求重放到新通道。

    服务器将为任何活动的 upload_id 推送 RemoteReadDataRequest、RemoteHashDataRequest 和 RemoteUploadStatusChanged 消息。

  3. 处理读取请求

    收到 RemoteReadDataRequest 时，从本地文件读取请求的范围并使用字节调用 RemoteReadData。当知道发送该上传的最后部分时设置 is_last_chunk。

  4. 处理哈希请求（带进度和完成）

    收到 RemoteHashDataRequest 时：

    • 从 hash_type 确定算法。
    • 如果 hash_type == MD5 且 block_size > 0，计算文件 MD5 和每块 MD5（小写十六进制，按顺序）。对于其他算法（例如 SHA1、PikPakSha1），仅计算文件哈希。
    • 哈希时，定期使用当前 bytes_hashed 调用 RemoteHashProgress。选择合理的频率（基于时间或字节）以避免过度调用。
    • 哈希完成时（或如果取消），发送最终的 RemoteHashProgress：
      • 成功时将 hash_value 设置为最终文件哈希。
      • 对于 block_size > 0 的 MD5，包含 block_hashes（小写十六进制，每块一个，按顺序）。
      • 如果哈希被取消，发送不带 hash_value 的终端进度。
    • 通过 RemoteHashProgress 报告进度。服务器在终端 RemoteHashProgress 上识别完成。
  5. 处理完成

    服务器将发送带有终端状态的 RemoteUploadStatusChanged（例如 Finish、Skipped、Cancelled、Error、FatalError）。将这些视为给定 upload_id 的完成信号。清理该上传的任何本地状态，但保持通道对其他上传开放。

  6. 控制操作

    使用 RemoteUploadControl 暂停、恢复或取消特定的 upload_id。不要在此处查询状态；状态更改作为 RemoteUploadStatusChanged 在通道上流式传输。

    • 取消：control = cancel {}
    • 暂停：control = pause {}
    • 恢复：control = resume {}
    • 响应：成功时返回 Empty（错误通过 gRPC 状态）

哈希详细信息

支持的算法（典型）：MD5、SHA1、PikPakSha1。服务器通过 RemoteHashDataRequest.hash_type 指示所需的算法。

MD5 块哈希（可选）

  • 服务器可以通过在 RemoteHashDataRequest 中提供 block_size（仅 MD5）来请求块哈希。
  • 计算大小为 block_size 的连续、非重叠块的每块 MD5 摘要（最后一块可能更小）。将每个摘要表示为 32 字符的小写十六进制字符串。
  • 当 block_size > 0 时，最终的 RemoteHashProgress 必须包含 hash_value（文件的 MD5）和 block_hashes（块 MD5 的有序列表）。

零长度文件

  • 文件哈希是算法对空字节流的摘要（例如空字符串的 MD5）。
  • 除非服务器特定约定另有指示，否则应省略/清空 block_hashes。

PikPakSha1 算法（规范）

PikPakSha1 不是对整个文件的普通 SHA-1。它是一个两级哈希：

  • 使用基于总文件大小的动态段大小将文件分割为连续段：
    • size ≤ 128 MiB: 256 KiB 段
    • 128 MiB < size ≤ 256 MiB: 512 KiB 段
    • 256 MiB < size ≤ 512 MiB: 1024 KiB 段
    • size > 512 MiB: 2048 KiB 段
  • 对于每个段，计算段字节的 SHA-1，生成 20 字节的摘要。
  • 连接这些每段摘要（按顺序）并计算连接的最终 SHA-1。
  • 将最终摘要输出为大写十六进制。
注意：
  • PikPakSha1 不使用 RemoteHashDataRequest 的 block_size；忽略该字段。
  • 进度（bytes_hashed）应反映到目前为止处理的字节，通常在每个段读取/哈希后递增。

进度语义和可靠性

  • 进度频率：在哈希期间定期发送 RemoteHashProgress，bytes_hashed 递增。在响应性和开销之间取得平衡（例如，每几百毫秒或有意义的字节增量后）。
  • 完成：服务器将最终的 RemoteHashProgress（存在 hash_value 的那个，以及如果请求了 block_hashes）视为该 (upload_id, hash_type) 的终端事件。
  • 重复请求：如果服务器观察到给定 (upload_id, hash_type) 在约 60 秒内没有 RemoteHashProgress，它可能会重新发送相应的 RemoteHashDataRequest。客户端必须幂等地处理此类重新请求（例如，如果已在进行中则忽略，或继续哈希并继续发送进度/最终）。
  • 客户端重启：当客户端使用相同的 device_id 重新连接时，服务器透明地替换旧的 RemoteUploadChannel 并重放任何未完成的 RemoteReadDataRequest 或 RemoteHashDataRequest 消息。保持按 upload_id 索引的本地上传状态，以便在收到重放的请求后立即恢复工作。
  • 取消：如果上传（或特定哈希请求）被取消，立即停止工作并发送不带 hash_value 的终端 RemoteHashProgress。服务器将相应地清理状态。

实现大纲（客户端）

  • 每个会话维护一个 RemoteUploadChannel 流和一个小型调度程序来处理传入请求。
  • 连接 RemoteUploadChannel 时提供稳定的 device_id；在本地持久化它，以便重新连接映射到相同的服务器端设备条目。
  • 对于每个 RemoteHashDataRequest，生成一个由 (upload_id, hash_type) 索引的哈希任务，以避免阻塞流读取器。
  • 使用与 upload_id 绑定的取消令牌在取消时立即停止哈希。
  • 将 RemoteHashProgress 更新限制在合理的速率；始终发送带有 hash_value 的终端进度（以及请求时的 MD5 的 block_hashes）。
  • 将相同 (upload_id, hash_type) 的重复 RemoteHashDataRequest 视为恢复/继续报告进度的提示。

C#（Grpc.Net.Client）

// 伪代码 — 假设生成的 gRPC 客户端类型存在。
using System;
using System.Buffers;
using System.Collections.Concurrent;
using System.Collections.Generic;
using System.IO;
using System.Security.Cryptography;
using System.Threading;
using System.Threading.Tasks;

async Task UploadClientAsync(CloudDrive.CloudDriveClient client, string path, long size, CancellationToken ct)
{
    var started = await client.StartRemoteUploadAsync(new StartRemoteUploadRequest {
        FilePath = path,
        FileSize = (ulong)size
    }, cancellationToken: ct);
    var files = new ConcurrentDictionary<string, (string path, long size)>();
    files[started.UploadId] = (path, size);

  var deviceId = MachineIdProvider.Current; // 稳定的每设备标识符
  using var channel = client.RemoteUploadChannel(new RemoteUploadChannelRequest { DeviceId = deviceId }, cancellationToken: ct);
    await foreach (var msg in channel.ResponseStream.ReadAllAsync(ct))
    {
        var uploadId = msg.UploadId;
        switch (msg.ReplyCase)
        {
            case RemoteUploadChannelReply.ReplyOneofCase.ReadData:
                _ = HandleReadAsync(client, uploadId, msg.ReadData, files, ct);
                break;
            case RemoteUploadChannelReply.ReplyOneofCase.HashData:
                _ = Task.Run(() => HandleHashAsync(client, uploadId, msg.HashData, files, ct), ct);
                break;
            case RemoteUploadChannelReply.ReplyOneofCase.StatusChanged:
                // 通过 msg.StatusChanged 观察完成/状态（如需要）
                break;
        }
    }
}

async Task HandleReadAsync(CloudDrive.CloudDriveClient client, string uploadId, RemoteReadDataRequest req,
                           ConcurrentDictionary<string,(string path,long size)> files, CancellationToken ct)
{
    var (localPath, totalSize) = files[uploadId];
    using var fs = File.OpenRead(localPath);
    fs.Position = (long)req.Offset;
    byte[] buffer = ArrayPool<byte>.Shared.Rent((int)req.Length);
    try
    {
        int read = await fs.ReadAsync(buffer.AsMemory(0, (int)req.Length), ct);
        bool isLast = (ulong)req.Offset + (ulong)Math.Max(0, read) >= (ulong)totalSize;
        await client.RemoteReadDataAsync(new RemoteReadDataUpload {
            UploadId = uploadId,
            Offset = req.Offset,
            Length = (ulong)Math.Max(0, read),
            LazyRead = req.LazyRead,
            Data = Google.Protobuf.ByteString.CopyFrom(buffer, 0, Math.Max(0, read)),
            IsLastChunk = isLast
        }, cancellationToken: ct);
    }
    finally { ArrayPool<byte>.Shared.Return(buffer); }
}

async Task HandleHashAsync(CloudDrive.CloudDriveClient client, string uploadId, RemoteHashDataRequest req,
                           ConcurrentDictionary<string,(string path,long size)> files, CancellationToken ct)
{
    var (localPath, totalSize) = files[uploadId];
    ulong bytesHashed = 0;
    DateTime lastReport = DateTime.UtcNow;

    void report(bool isFinal, string? hashValue = null, List<string>? blockHashes = null)
    {
        if (!isFinal && (DateTime.UtcNow - lastReport).TotalMilliseconds < 250) return;
        lastReport = DateTime.UtcNow;
        client.RemoteHashProgress(new RemoteHashProgressUpload {
            UploadId = uploadId,
            TotalBytes = (ulong)totalSize,
            HashType = req.HashType,
            BytesHashed = bytesHashed,
            HashValue = hashValue ?? string.Empty,
            BlockHashes = { blockHashes ?? new List<string>() }
        });
    }

  using var fs = File.OpenRead(localPath);
  if (req.HashType == HashType.Md5 && req.BlockSize > 0)
    {
        using var md5File = MD5.Create();
        var blocks = new List<string>();
        byte[] block = new byte[req.BlockSize];
        int n;
        while ((n = await fs.ReadAsync(block, 0, block.Length, ct)) > 0)
        {
            md5File.TransformBlock(block, 0, n, null, 0);
            using var md5 = MD5.Create();
            blocks.Add(Convert.ToHexString(md5.ComputeHash(block, 0, n)).ToLowerInvariant());
            bytesHashed += (ulong)n;
            report(false);
            if (ct.IsCancellationRequested) { report(true); return; }
        }
        md5File.TransformFinalBlock(Array.Empty<byte>(), 0, 0);
        report(true, Convert.ToHexString(md5File.Hash!).ToLowerInvariant(), blocks);
  }
  else if (req.HashType == HashType.PikPakSha1)
  {
    // PikPakSha1: SHA1 对每段 SHA1 摘要的连接；动态段大小
    int segSize = totalSize <= (128L<<20) ? (256<<10) :
            (totalSize <= (256L<<20) ? (512<<10) :
            (totalSize <= (512L<<20) ? (1024<<10) : (2048<<10)));
    using var finalSha1 = SHA1.Create();
    byte[] buf = new byte[segSize];
    int n;
    while ((n = await fs.ReadAsync(buf, 0, buf.Length, ct)) > 0)
    {
      using var seg = SHA1.Create();
      seg.TransformBlock(buf, 0, n, null, 0);
      seg.TransformFinalBlock(Array.Empty<byte>(), 0, 0);
      finalSha1.TransformBlock(seg.Hash!, 0, seg.Hash!.Length, null, 0);
      bytesHashed += (ulong)n;
      report(false);
      if (ct.IsCancellationRequested) { report(true); return; }
    }
    finalSha1.TransformFinalBlock(Array.Empty<byte>(), 0, 0);
    report(true, Convert.ToHexString(finalSha1.Hash!).ToUpperInvariant());
  }
  else
    {
        using var hash = req.HashType == HashType.Sha1 ? SHA1.Create() : MD5.Create();
        byte[] buf = new byte[1 << 20];
        int n;
        while ((n = await fs.ReadAsync(buf, 0, buf.Length, ct)) > 0)
        {
            hash.TransformBlock(buf, 0, n, null, 0);
            bytesHashed += (ulong)n;
            report(false);
            if (ct.IsCancellationRequested) { report(true); return; }
        }
        hash.TransformFinalBlock(Array.Empty<byte>(), 0, 0);
        report(true, Convert.ToHexString(hash.Hash!).ToLowerInvariant());
    }
}

Java（grpc-java）

// 伪代码 — 假设生成的存根存在。
void startUpload(CloudDriveGrpc.CloudDriveBlockingStub blocking,
                 CloudDriveGrpc.CloudDriveStub async,
                 String path, long size, Context.CancellableContext ctx) {
  StartRemoteUploadRequest sreq = StartRemoteUploadRequest.newBuilder()
      .setFilePath(path).setFileSize(size).build();
  RemoteUploadStarted started = blocking.startRemoteUpload(sreq);
  Map<String, LocalFile> files = new ConcurrentHashMap<>();
  files.put(started.getUploadId(), new LocalFile(path, size));

  String deviceId = MachineIdProvider.get();
  RemoteUploadChannelRequest channelReq = RemoteUploadChannelRequest.newBuilder()
      .setDeviceId(deviceId)
      .build();
  async.remoteUploadChannel(channelReq, new StreamObserver<RemoteUploadChannelReply>() {
    @Override public void onNext(RemoteUploadChannelReply msg) {
      String uploadId = msg.getUploadId();
      switch (msg.getReplyCase()) {
        case READDATA:
          handleRead(blocking, uploadId, msg.getReadData(), files);
          break;
        case HASHDATA:
          CompletableFuture.runAsync(() -> handleHash(blocking, uploadId, msg.getHashData(), files, ctx));
          break;
        case STATUSCHANGED:
          // 通过状态观察完成
          break;
        default: break;
      }
    }
    @Override public void onError(Throwable t) { }
    @Override public void onCompleted() { }
  });
}

void handleRead(CloudDriveGrpc.CloudDriveBlockingStub blocking, String uploadId, RemoteReadDataRequest req, Map<String, LocalFile> files) {
  try (RandomAccessFile raf = new RandomAccessFile(files.get(uploadId).path, "r")) {
    raf.seek(req.getOffset());
    byte[] buf = new byte[(int)req.getLength()];
    int read = raf.read(buf);
    boolean isLast = req.getOffset() + Math.max(0, read) >= files.get(uploadId).size;
    RemoteReadDataUpload up = RemoteReadDataUpload.newBuilder()
        .setUploadId(uploadId)
        .setOffset(req.getOffset())
        .setLength(Math.max(0, read))
        .setLazyRead(req.getLazyRead())
        .setData(ByteString.copyFrom(buf, 0, Math.max(0, read)))
        .setIsLastChunk(isLast)
        .build();
    blocking.remoteReadData(up);
  } catch (IOException e) { }
}

void handleHash(CloudDriveGrpc.CloudDriveBlockingStub blocking, String uploadId, RemoteHashDataRequest req, Map<String, LocalFile> files, Context.CancellableContext ctx) {
  File f = new File(files.get(uploadId).path);
  long bytesHashed = 0L;
  try (FileInputStream fis = new FileInputStream(f)) {
  if (req.getHashType() == HashType.MD5 && req.getBlockSize() > 0) {
      MessageDigest fileMd5 = MessageDigest.getInstance("MD5");
      List<String> blocks = new ArrayList<>();
      byte[] block = new byte[req.getBlockSize()];
      int n;
      while ((n = fis.read(block)) > 0) {
        fileMd5.update(block, 0, n);
        MessageDigest md5 = MessageDigest.getInstance("MD5");
        md5.update(block, 0, n);
        blocks.add(bytesToHex(md5.digest()).toLowerCase());
        bytesHashed += n;
        maybeProgress(blocking, uploadId, req, f.length(), bytesHashed, null, null);
        if (ctx.isCancelled()) { finalProgress(blocking, uploadId, req, f.length(), bytesHashed, null, null); return; }
      }
      finalProgress(blocking, uploadId, req, f.length(), bytesHashed, bytesToHex(fileMd5.digest()).toLowerCase(), blocks);
    } else if (req.getHashType() == HashType.PIKPAKSHA1) {
      // PikPakSha1: 连接的每段 SHA1 摘要的 SHA1
      int segSize = f.length() <= (128L<<20) ? (256<<10) :
                    (f.length() <= (256L<<20) ? (512<<10) :
                    (f.length() <= (512L<<20) ? (1024<<10) : (2048<<10)));
      MessageDigest finalSha1;
      try { finalSha1 = MessageDigest.getInstance("SHA-1"); } catch (Exception e) { return; }
      byte[] buf = new byte[segSize];
      int n;
      try (BufferedInputStream bis = new BufferedInputStream(new FileInputStream(f))) {
        while ((n = bis.read(buf)) > 0) {
          MessageDigest seg = MessageDigest.getInstance("SHA-1");
          seg.update(buf, 0, n);
          byte[] segDigest = seg.digest();
          finalSha1.update(segDigest);
          bytesHashed += n;
          maybeProgress(blocking, uploadId, req, f.length(), bytesHashed, null, null);
          if (ctx.isCancelled()) { finalProgress(blocking, uploadId, req, f.length(), bytesHashed, null, null); return; }
        }
      } catch (IOException | NoSuchAlgorithmException e) { return; }
      finalProgress(blocking, uploadId, req, f.length(), bytesHashed, bytesToHex(finalSha1.digest()).toUpperCase(), null);
    } else {
      MessageDigest dig = req.getHashType() == HashType.SHA1 ? MessageDigest.getInstance("SHA-1") : MessageDigest.getInstance("MD5");
      byte[] buf = new byte[1 << 20];
      int n;
      while ((n = fis.read(buf)) > 0) {
        dig.update(buf, 0, n);
        bytesHashed += n;
        maybeProgress(blocking, uploadId, req, f.length(), bytesHashed, null, null);
        if (ctx.isCancelled()) { finalProgress(blocking, uploadId, req, f.length(), bytesHashed, null, null); return; }
      }
      finalProgress(blocking, uploadId, req, f.length(), bytesHashed, bytesToHex(dig.digest()).toLowerCase(), null);
    }
  } catch (Exception e) { }
}

import hashlib, os, time

def upload_client(stub, path, size, cancel_event):
    started = stub.StartRemoteUpload(StartRemoteUploadRequest(file_path=path, file_size=size))
    files = {started.upload_id: {'path': path, 'size': size}}

  device_id = machine_id_provider()  # 返回稳定的每设备标识符
  channel_request = RemoteUploadChannelRequest(device_id=device_id)

  for msg in stub.RemoteUploadChannel(channel_request):
        uid = msg.upload_id
        which = msg.WhichOneof('request')
        if which == 'read_data':
            handle_read(stub, uid, msg.read_data, files)
        elif which == 'hash_data':
            handle_hash(stub, uid, msg.hash_data, files, cancel_event)
        elif which == 'status_changed':
            pass

def handle_read(stub, upload_id, req, files):
    local = files[upload_id]
    with open(local['path'], 'rb') as f:
        f.seek(req.offset)
        data = f.read(req.length)
    is_last = (req.offset + len(data)) >= local['size']
    stub.RemoteReadData(RemoteReadDataUpload(
        upload_id=upload_id,
        offset=req.offset,
        length=len(data),
        lazy_read=req.lazy_read,
        data=data,
        is_last_chunk=is_last,
    ))

def handle_hash(stub, upload_id, req, files, cancel_event):
    local = files[upload_id]
    file_size = local['size']
    bytes_hashed = 0
    last_report = 0.0

    def progress(final=False, hash_value='', block_hashes=None):
        nonlocal last_report
        now = time.time()
        if not final and (now - last_report) < 0.25:
            return
        last_report = now
        stub.RemoteHashProgress(RemoteHashProgressUpload(
            upload_id=upload_id,
            bytes_hashed=bytes_hashed,
            total_bytes=file_size,
            hash_type=req.hash_type,
            hash_value=hash_value,
            block_hashes=block_hashes or [],
        ))

  with open(local['path'], 'rb') as f:
    if req.hash_type == HashType.MD5 and req.block_size > 0:
            md5_file = hashlib.md5()
            blocks = []
            while True:
                chunk = f.read(req.block_size)
                if not chunk:
                    break
                md5_file.update(chunk)
                blocks.append(hashlib.md5(chunk).hexdigest())
                bytes_hashed += len(chunk)
                progress()
                if cancel_event.is_set():
                    progress(final=True)
                    return
            progress(final=True, hash_value=md5_file.hexdigest(), block_hashes=blocks)
    elif req.hash_type == HashType.PIKPAKSHA1:
      # PikPakSha1: 每段 SHA1 摘要连接的 SHA1（大写十六进制）
      size = file_size
      if size <= (128 << 20):
        seg = 256 << 10
      elif size <= (256 << 20):
        seg = 512 << 10
      elif size <= (512 << 20):
        seg = 1024 << 10
      else:
        seg = 2048 << 10
      final = hashlib.sha1()
      while True:
        chunk = f.read(seg)
        if not chunk:
          break
        final.update(hashlib.sha1(chunk).digest())
        bytes_hashed += len(chunk)
        progress()
        if cancel_event.is_set():
          progress(final=True)
          return
      progress(final=True, hash_value=final.hexdigest().upper())
    else:
            dig = hashlib.sha1() if req.hash_type == HashType.SHA1 else hashlib.md5()
            while True:
                chunk = f.read(1 << 20)
                if not chunk:
                    break
                dig.update(chunk)
                bytes_hashed += len(chunk)
                progress()
                if cancel_event.is_set():
                    progress(final=True)
                    return
            progress(final=True, hash_value=dig.hexdigest())

最佳实践

  • 始终在每个 RPC 上包含正确的 upload_id。
  • 为 RemoteUploadChannel 请求重用稳定的 device_id，以便恢复连接被视为同一设备，并自动重放待处理的工作。
  • 保持流通道打开；不要为每个文件创建一个通道。
  • 对于数据传输，优先使用 ≤ 1 MiB 的块大小以保持在典型的 gRPC 消息限制之下并减少背压（根据需要调整）。
  • 在 StartRemoteUpload 时验证 file_path 和 file_size 以尽早发现不匹配。
  • 对于大文件，优先使用内存映射或缓冲 I/O 和增量哈希以最小化内存使用。
  • 日志/跟踪：检测进度和完成点以辅助诊断。
  • 退避和重试：发送进度或数据时的瞬态 RPC 失败应使用抖动重试；避免重复最终消息，除非您不确定服务器是否收到它们。

错误处理

  • 一元 RPC 返回标准 gRPC 状态代码；在安全的情况下处理重试。
  • 如果 RemoteHashProgress 暂时失败，重试发送最新进度（包括最终进度）。服务器基于 (upload_id, hash_type) 和终端状态去重。
  • 如果服务器取消上传，停止哈希/读取，并在适用时发送不带 hash_value 的终端 RemoteHashProgress。

Remote File Upload (Client Developer Guide)

This guide explains how to implement a client that uploads files to a remote CloudDrive gRPC server. It focuses on the client-side workflow, progress reporting, hashing (including optional MD5 block hashes), cancellation, and reliability behaviors.

RPCs and messages at a glance

  • StartRemoteUpload (unary)
    • Request: StartRemoteUploadRequest
    • Response: RemoteUploadStarted
  • RemoteUploadChannel (server-side streaming; use one long-lived channel per client session)
    • Request: RemoteUploadChannelRequest
    • Response: RemoteUploadChannelReply
      • Fields: upload_id
      • oneof request
        • read_data: RemoteReadDataRequest
        • hash_data: RemoteHashDataRequest
        • status_changed: RemoteUploadStatusChanged
  • RemoteReadData (unary)
    • Request: RemoteReadDataUpload
    • Response: RemoteReadDataReply
  • RemoteHashProgress (unary) — used for progress updates and finalization of hash requests
    • Request: RemoteHashProgressUpload
    • Response: RemoteHashProgressReply
  • RemoteUploadControl (unary)
    • Request: RemoteUploadControlRequest (oneof: cancel, pause, resume)
    • Response: google.protobuf.Empty (errors via RPC status)
Key protocol notes:
  • All operations are keyed by a server-provided upload_id (returned from StartRemoteUpload).
  • RemoteUploadChannel requests must include a stable device_id that uniquely identifies the client device; reuse it across restarts so the server can replace the channel and replay pending work if the client reconnects.
  • file_path is provided in StartRemoteUpload only; subsequent messages are keyed by upload_id. No cloudName/cloudAccountId is used.
  • Server requests for hashing may include an optional block_size (MD5-only) to request per-block MD5s.
  • The final hash value (and any block hashes) MUST be delivered via RemoteHashProgress.
  • Client-side control (pause/resume/cancel) is sent via RemoteUploadControl. Status changes are observed on the stream via RemoteUploadStatusChanged; the control RPC returns Empty on success and does not carry status.

Message contracts (essential fields)

StartRemoteUploadRequest

  • file_path: string — desired path on server
  • file_size: uint64 — total bytes
  • known_hashes: map<uint32, string> — optional precomputed file hashes; keys are CloudDriveFile.HashType numeric values (1=MD5, 2=SHA1, 3=PIKPAK_SHA1)

RemoteUploadChannelRequest

  • device_id: string — stable identifier for the client device. Reuse the same value across process restarts (e.g., the CloudFS SELF_GENERATE_MACHINE_ID).

RemoteUploadChannelReply

  • upload_id: string
  • oneof request
    • RemoteReadDataRequest
      • offset: uint64
      • length: uint64
      • lazy_read: bool
    • RemoteHashDataRequest
      • hash_type: HashType (e.g., MD5, SHA1, PIKPAK_SHA1)
      • block_size: uint32 (optional; MD5-only; 0 or unset means no per-block hashes)
    • RemoteUploadStatusChanged
      • status: UploadFileInfo.Status (e.g., WaitforPreprocessing, Preprocessing, Transfer, Pause, Cancelled, Finish, Skipped, Inqueue, Ignored, Error, FatalError)
      • error_message: string (set when status indicates an error)

RemoteReadDataUpload

  • upload_id: string
  • offset: uint64
  • length: uint64
  • lazy_read: bool
  • data: bytes
  • is_last_chunk: bool

RemoteHashProgressUpload

  • upload_id: string
  • bytes_hashed: uint64 — cumulative progress
  • total_bytes: uint64 — usually the file size
  • hash_type: HashType
  • hash_value: string (optional; present only on the final progress message)
  • block_hashes: repeated string (optional; MD5-only; present only on the final progress message when block_size > 0)

End-to-end client workflow

  1. Start the upload

    Call StartRemoteUpload with file_path and file_size. Use the returned upload_id for all subsequent RPCs.

  2. Open the global channel

    Call RemoteUploadChannel once per client session and keep it open. Supply the same device_id every time you connect (even after restarting the process). The server uses device_id to swap in the newest stream for that device and will automatically replay any outstanding read/hash requests to the fresh channel.

    The server will push RemoteReadDataRequest, RemoteHashDataRequest, and RemoteUploadStatusChanged messages for any active upload_id.

  3. Serve read requests

    Upon RemoteReadDataRequest, read the requested range from the local file and call RemoteReadData with the bytes. Set is_last_chunk when you know you're sending the final portion for that upload.

  4. Serve hash requests (with progress and finalization)

    Upon RemoteHashDataRequest:

    • Determine the algorithm from hash_type.
    • If hash_type == MD5 and block_size > 0, compute both the file MD5 and per-block MD5s (lower-hex, in order). For other algorithms (e.g., SHA1, PikPakSha1), compute only the file hash.
    • While hashing, periodically call RemoteHashProgress with the current bytes_hashed. Choose a reasonable cadence (time- or byte-based) to avoid spamming.
    • When hashing completes (or if canceled), send a final RemoteHashProgress:
      • Set hash_value to the final file hash when successful.
      • For MD5 with block_size > 0, include block_hashes (lower-hex, one per block, ordered).
      • If hashing is canceled, send a terminal progress without hash_value.
    • Report progress via RemoteHashProgress. Finalization is recognized by the server on the terminal RemoteHashProgress.
  5. Handle completion

    The server will send RemoteUploadStatusChanged with a terminal state (e.g., Finish, Skipped, Cancelled, Error, FatalError). Treat these as completion signals for the given upload_id. Clean up any local state for that upload, but keep the channel open for other uploads.

  6. Control operations

    Use RemoteUploadControl to pause, resume, or cancel a specific upload_id. Do not query status here; status changes are streamed as RemoteUploadStatusChanged on the channel.

    • Cancel: control = cancel {}
    • Pause: control = pause {}
    • Resume: control = resume {}
    • Response: Empty on success (errors via gRPC status)

Hashing details

Supported algorithms (typical): MD5, SHA1, PikPakSha1. The server indicates the desired algorithm via RemoteHashDataRequest.hash_type.

MD5 block hashes (optional)

  • The server may request block hashes by providing block_size in RemoteHashDataRequest (MD5-only).
  • Compute per-block MD5 digests over contiguous, non-overlapping blocks of size block_size (the final block may be smaller). Represent each digest as a 32-char lower-hex string.
  • The final RemoteHashProgress must include both hash_value (the file's MD5) and block_hashes (ordered list of block MD5s) when block_size > 0.

Zero-length files

  • The file hash is the algorithm's digest of an empty byte stream (e.g., MD5 of empty string).
  • block_hashes should be omitted/empty unless otherwise directed by server-specific conventions.

PikPakSha1 algorithm (spec)

PikPakSha1 is not a plain SHA-1 over the entire file. It's a two-level hash:

  • Split the file into contiguous segments using a dynamic segment size based on the total file size:
    • size ≤ 128 MiB: 256 KiB segments
    • 128 MiB < size ≤ 256 MiB: 512 KiB segments
    • 256 MiB < size ≤ 512 MiB: 1024 KiB segments
    • size > 512 MiB: 2048 KiB segments
  • For each segment, compute SHA-1 over the segment bytes, producing a 20-byte digest.
  • Concatenate these per-segment digests (in order) and compute a final SHA-1 over the concatenation.
  • Output the final digest as UPPERCASE hex.
Notes:
  • PikPakSha1 does not use block_size from RemoteHashDataRequest; ignore that field for this algorithm.
  • Progress (bytes_hashed) should reflect bytes processed so far, typically incremented after each segment is read/hashed.

Progress semantics and reliability

  • Progress cadence: Send RemoteHashProgress periodically during hashing with increasing bytes_hashed. Aim for a balance between responsiveness and overhead (for example, every few hundred milliseconds or after meaningful byte increments).
  • Finalization: The server treats the final RemoteHashProgress (the one where hash_value is present, and block_hashes if requested) as the terminal event for that (upload_id, hash_type).
  • Duplicate requests: If the server observes no RemoteHashProgress for a given (upload_id, hash_type) for ~60 seconds, it may re-send the corresponding RemoteHashDataRequest. Clients must handle such re-requests idempotently (e.g., ignore if already in progress, or continue hashing and keep sending progress/final).
  • Client restarts: When a client reconnects with the same device_id, the server transparently replaces the old RemoteUploadChannel and replays any outstanding RemoteReadDataRequest or RemoteHashDataRequest messages. Keep your local upload state keyed by upload_id so you can resume work immediately upon receiving the replayed requests.
  • Cancellation: If the upload (or specific hash request) is canceled, stop work promptly and send a terminal RemoteHashProgress without hash_value. The server will clean up state accordingly.

Implementation outline (client)

  • Maintain a single RemoteUploadChannel stream per session and a small dispatcher to handle incoming requests.
  • Provide a stable device_id whenever you connect RemoteUploadChannel; persist it locally so reconnects map to the same server-side device entry.
  • For each RemoteHashDataRequest, spawn a hashing task keyed by (upload_id, hash_type) to avoid blocking the stream reader.
  • Use a cancellation token tied to upload_id to stop hashing promptly when canceled.
  • Throttle RemoteHashProgress updates to a reasonable rate; always send the terminal progress with hash_value (and block_hashes for MD5 when requested).
  • Treat repeated RemoteHashDataRequest for the same (upload_id, hash_type) as hints to resume/continue reporting progress.

async Task HandleReadAsync(CloudDrive.CloudDriveClient client, string uploadId, RemoteReadDataRequest req,
                           ConcurrentDictionary<string,(string path,long size)> files, CancellationToken ct)
{
    var (localPath, totalSize) = files[uploadId];
    using var fs = File.OpenRead(localPath);
    fs.Position = (long)req.Offset;
    byte[] buffer = ArrayPool<byte>.Shared.Rent((int)req.Length);
    try
    {
        int read = await fs.ReadAsync(buffer.AsMemory(0, (int)req.Length), ct);
        bool isLast = (ulong)req.Offset + (ulong)Math.Max(0, read) >= (ulong)totalSize;
        await client.RemoteReadDataAsync(new RemoteReadDataUpload {
            UploadId = uploadId,
            Offset = req.Offset,
            Length = (ulong)Math.Max(0, read),
            LazyRead = req.LazyRead,
            Data = Google.Protobuf.ByteString.CopyFrom(buffer, 0, Math.Max(0, read)),
            IsLastChunk = isLast
        }, cancellationToken: ct);
    }
    finally { ArrayPool<byte>.Shared.Return(buffer); }
}

async Task HandleHashAsync(CloudDrive.CloudDriveClient client, string uploadId, RemoteHashDataRequest req,
                           ConcurrentDictionary<string,(string path,long size)> files, CancellationToken ct)
{
    var (localPath, totalSize) = files[uploadId];
    ulong bytesHashed = 0;
    DateTime lastReport = DateTime.UtcNow;

    void report(bool isFinal, string? hashValue = null, List<string>? blockHashes = null)
    {
        if (!isFinal && (DateTime.UtcNow - lastReport).TotalMilliseconds < 250) return;
        lastReport = DateTime.UtcNow;
        client.RemoteHashProgress(new RemoteHashProgressUpload {
            UploadId = uploadId,
            TotalBytes = (ulong)totalSize,
            HashType = req.HashType,
            BytesHashed = bytesHashed,
            HashValue = hashValue ?? string.Empty,
            BlockHashes = { blockHashes ?? new List<string>() }
        });
    }

  using var fs = File.OpenRead(localPath);
  if (req.HashType == HashType.Md5 && req.BlockSize > 0)
    {
        using var md5File = MD5.Create();
        var blocks = new List<string>();
        byte[] block = new byte[req.BlockSize];
        int n;
        while ((n = await fs.ReadAsync(block, 0, block.Length, ct)) > 0)
        {
            md5File.TransformBlock(block, 0, n, null, 0);
            using var md5 = MD5.Create();
            blocks.Add(Convert.ToHexString(md5.ComputeHash(block, 0, n)).ToLowerInvariant());
            bytesHashed += (ulong)n;
            report(false);
            if (ct.IsCancellationRequested) { report(true); return; }
        }
        md5File.TransformFinalBlock(Array.Empty<byte>(), 0, 0);
        report(true, Convert.ToHexString(md5File.Hash!).ToLowerInvariant(), blocks);
  }
  else if (req.HashType == HashType.PikPakSha1)
  {
    // PikPakSha1: SHA1 over concatenation of per-segment SHA1 digests; dynamic segment size
    int segSize = totalSize <= (128L<<20) ? (256<<10) :
            (totalSize <= (256L<<20) ? (512<<10) :
            (totalSize <= (512L<<20) ? (1024<<10) : (2048<<10)));
    using var finalSha1 = SHA1.Create();
    byte[] buf = new byte[segSize];
    int n;
    while ((n = await fs.ReadAsync(buf, 0, buf.Length, ct)) > 0)
    {
      using var seg = SHA1.Create();
      seg.TransformBlock(buf, 0, n, null, 0);
      seg.TransformFinalBlock(Array.Empty<byte>(), 0, 0);
      finalSha1.TransformBlock(seg.Hash!, 0, seg.Hash!.Length, null, 0);
      bytesHashed += (ulong)n;
      report(false);
      if (ct.IsCancellationRequested) { report(true); return; }
    }
    finalSha1.TransformFinalBlock(Array.Empty<byte>(), 0, 0);
    report(true, Convert.ToHexString(finalSha1.Hash!).ToUpperInvariant());
  }
  else
    {
        using var hash = req.HashType == HashType.Sha1 ? SHA1.Create() : MD5.Create();
        byte[] buf = new byte[1 << 20];
        int n;
        while ((n = await fs.ReadAsync(buf, 0, buf.Length, ct)) > 0)
        {
            hash.TransformBlock(buf, 0, n, null, 0);
            bytesHashed += (ulong)n;
            report(false);
            if (ct.IsCancellationRequested) { report(true); return; }
        }
        hash.TransformFinalBlock(Array.Empty<byte>(), 0, 0);
        report(true, Convert.ToHexString(hash.Hash!).ToLowerInvariant());
    }
}

// Pseudocode — assumes generated stubs exist.
void startUpload(CloudDriveGrpc.CloudDriveBlockingStub blocking,
                 CloudDriveGrpc.CloudDriveStub async,
                 String path, long size, Context.CancellableContext ctx) {
  StartRemoteUploadRequest sreq = StartRemoteUploadRequest.newBuilder()
      .setFilePath(path).setFileSize(size).build();
  RemoteUploadStarted started = blocking.startRemoteUpload(sreq);
  Map<String, LocalFile> files = new ConcurrentHashMap<>();
  files.put(started.getUploadId(), new LocalFile(path, size));

  String deviceId = MachineIdProvider.get();
  RemoteUploadChannelRequest channelReq = RemoteUploadChannelRequest.newBuilder()
      .setDeviceId(deviceId)
      .build();
  async.remoteUploadChannel(channelReq, new StreamObserver<RemoteUploadChannelReply>() {
    @Override public void onNext(RemoteUploadChannelReply msg) {
      String uploadId = msg.getUploadId();
      switch (msg.getReplyCase()) {
        case READDATA:
          handleRead(blocking, uploadId, msg.getReadData(), files);
          break;
        case HASHDATA:
          CompletableFuture.runAsync(() -> handleHash(blocking, uploadId, msg.getHashData(), files, ctx));
          break;
        case STATUSCHANGED:
          // observe completion via status
          break;
        default: break;
      }
    }
    @Override public void onError(Throwable t) { }
    @Override public void onCompleted() { }
  });
}

void handleRead(CloudDriveGrpc.CloudDriveBlockingStub blocking, String uploadId, RemoteReadDataRequest req, Map<String, LocalFile> files) {
  try (RandomAccessFile raf = new RandomAccessFile(files.get(uploadId).path, "r")) {
    raf.seek(req.getOffset());
    byte[] buf = new byte[(int)req.getLength()];
    int read = raf.read(buf);
    boolean isLast = req.getOffset() + Math.max(0, read) >= files.get(uploadId).size;
    RemoteReadDataUpload up = RemoteReadDataUpload.newBuilder()
        .setUploadId(uploadId)
        .setOffset(req.getOffset())
        .setLength(Math.max(0, read))
        .setLazyRead(req.getLazyRead())
        .setData(ByteString.copyFrom(buf, 0, Math.max(0, read)))
        .setIsLastChunk(isLast)
        .build();
    blocking.remoteReadData(up);
  } catch (IOException e) { }
}

void handleHash(CloudDriveGrpc.CloudDriveBlockingStub blocking, String uploadId, RemoteHashDataRequest req, Map<String, LocalFile> files, Context.CancellableContext ctx) {
  File f = new File(files.get(uploadId).path);
  long bytesHashed = 0L;
  try (FileInputStream fis = new FileInputStream(f)) {
  if (req.getHashType() == HashType.MD5 && req.getBlockSize() > 0) {
      MessageDigest fileMd5 = MessageDigest.getInstance("MD5");
      List<String> blocks = new ArrayList<>();
      byte[] block = new byte[req.getBlockSize()];
      int n;
      while ((n = fis.read(block)) > 0) {
        fileMd5.update(block, 0, n);
        MessageDigest md5 = MessageDigest.getInstance("MD5");
        md5.update(block, 0, n);
        blocks.add(bytesToHex(md5.digest()).toLowerCase());
        bytesHashed += n;
        maybeProgress(blocking, uploadId, req, f.length(), bytesHashed, null, null);
        if (ctx.isCancelled()) { finalProgress(blocking, uploadId, req, f.length(), bytesHashed, null, null); return; }
      }
      finalProgress(blocking, uploadId, req, f.length(), bytesHashed, bytesToHex(fileMd5.digest()).toLowerCase(), blocks);
    } else if (req.getHashType() == HashType.PIKPAKSHA1) {
      // PikPakSha1: SHA1 of concatenated per-segment SHA1 digests
      int segSize = f.length() <= (128L<<20) ? (256<<10) :
                    (f.length() <= (256L<<20) ? (512<<10) :
                    (f.length() <= (512L<<20) ? (1024<<10) : (2048<<10)));
      MessageDigest finalSha1;
      try { finalSha1 = MessageDigest.getInstance("SHA-1"); } catch (Exception e) { return; }
      byte[] buf = new byte[segSize];
      int n;
      try (BufferedInputStream bis = new BufferedInputStream(new FileInputStream(f))) {
        while ((n = bis.read(buf)) > 0) {
          MessageDigest seg = MessageDigest.getInstance("SHA-1");
          seg.update(buf, 0, n);
          byte[] segDigest = seg.digest();
          finalSha1.update(segDigest);
          bytesHashed += n;
          maybeProgress(blocking, uploadId, req, f.length(), bytesHashed, null, null);
          if (ctx.isCancelled()) { finalProgress(blocking, uploadId, req, f.length(), bytesHashed, null, null); return; }
        }
      } catch (IOException | NoSuchAlgorithmException e) { return; }
      finalProgress(blocking, uploadId, req, f.length(), bytesHashed, bytesToHex(finalSha1.digest()).toUpperCase(), null);
    } else {
      MessageDigest dig = req.getHashType() == HashType.SHA1 ? MessageDigest.getInstance("SHA-1") : MessageDigest.getInstance("MD5");
      byte[] buf = new byte[1 << 20];
      int n;
      while ((n = fis.read(buf)) > 0) {
        dig.update(buf, 0, n);
        bytesHashed += n;
        maybeProgress(blocking, uploadId, req, f.length(), bytesHashed, null, null);
        if (ctx.isCancelled()) { finalProgress(blocking, uploadId, req, f.length(), bytesHashed, null, null); return; }
      }
      finalProgress(blocking, uploadId, req, f.length(), bytesHashed, bytesToHex(dig.digest()).toLowerCase(), null);
    }
  } catch (Exception e) { }
}

Best practices

  • Always include the correct upload_id on every RPC.
  • Reuse a stable device_id for the RemoteUploadChannel request so resumed connections are treated as the same device and pending work is replayed automatically.
  • Keep the streaming channel open; do not create one channel per file.
  • For data transfers, prefer chunk sizes ≤ 1 MiB to stay under typical gRPC message limits and reduce backpressure (tune as needed).
  • Validate file_path and file_size at StartRemoteUpload time to catch mismatches early.
  • For large files, prefer memory-mapped or buffered I/O and incremental hashing to minimize memory usage.
  • Log/tracing: instrument progress and finalization points to aid diagnostics.
  • Backoff and retry: transient RPC failures when sending progress or data should be retried with jitter; avoid duplicating final messages unless you're unsure the server received them.

Error handling

  • Unary RPCs return standard gRPC status codes; handle retries where safe.
  • If RemoteHashProgress fails transiently, retry sending the latest progress (including the final one). The server deduplicates based on (upload_id, hash_type) and terminal state.
  • If the server cancels an upload, cease hashing/reading and send a terminal RemoteHashProgress without hash_value if applicable.
