核心服务 · 网页管理界面

网页播放器

1.2.0 公开 Beta 测试 · 网页播放器

核心服务的网页管理界面自带播放器：在文件管理中点视频、音乐、光盘镜像或 CUE 整轨，就在浏览器里播放，不需要安装应用，也不需要开启媒体服务器。开启媒体服务器后，「媒体」页面中的影片和音乐也用它播放。浏览器能直接播放的格式交给浏览器，其他受支持的格式在页面中解封装、解码和渲染，覆盖绝大多数常见音视频格式，服务器不转码。具体格式和输出限制见下文。

在哪里使用

从文件管理或媒体库打开

文件管理

在网页管理界面的文件管理中点视频、音乐、光盘镜像（.iso）、CUE 整轨，或蓝光文件夹中的 index.bdmv，就在播放器中打开。同一个文件夹中的视频或歌曲依次播放，可以用 N 和 P 键切换。不需要开启媒体服务器。

播放位置记在这个浏览器中，下次打开同一个文件时从上次的位置继续。

媒体库

开启媒体服务器后，「媒体」页面中的电影、剧集和音乐也用这个播放器播放。播放进度和已看与服务器同步，其他设备和 CloudDrive2 App 都能看到；剧集可以跳过片头片尾，播完自动播放下一集；分成几段的电影依次播放。见在浏览器中观看。

会员

文件管理中的播放不需要会员。HDR、杜比视界、蓝光 ISO、DSD 和 SACD 需要 App Pro，没有时可以试播 10 秒。「媒体」页面需要媒体服务器，也就是服务器账号同时有核心会员和 App Pro。见会员与价格。

视频

视频播放

格式

  • 格式：浏览器能直接播放的由浏览器播放，其他的在页面中解码：MKV、MP4、AVI、TS、M2TS、FLV、MPG、VOB、OGG；H.264、HEVC、AV1、VP9、MPEG-2、MPEG-4；AC-3、E-AC-3、DTS、TrueHD、FLAC、Opus 等声音。两种方式能用的功能不同，见两种播放方式。
  • 蓝光 ISO：播放正片，包括它的音轨、字幕和章节，由服务器读取光盘。蓝光文件夹在文件管理中打开 index.bdmv。没有光碟菜单。
  • HDR：浏览器直接播放时，按浏览器和显示器的能力显示 HDR；在页面中解码时可能转为 SDR 显示。
  • 杜比视界：Safari 中 Profile 5 和 8 以杜比视界播放，这时 TrueHD 和 DTS 声音改用同一语言的 AC-3、E-AC-3 或 AAC 音轨。Chrome 和 Edge 中 Profile 5 用 WebGPU 转换为颜色正确的 SDR 画面，其他的显示 HDR10 基础层。
  • 声音：杜比全景声和 DTS:X 播放其基础声道；蓝光中的 DTS-HD MA 播放其核心部分。在页面中解码的声音以立体声输出。
  • 没有记录画面显示时间的 MP4 也能平稳播放，不会抖动。
  • 不能播放的（DVD、VC-1、RMVB、WMV 等）显示「复制链接」和「下载」，可以用 VLC、IINA、PotPlayer 或 Infuse 播放，也可以用 CloudDrive2 App 播放。

字幕和控制

  • 字幕：SRT、WebVTT 和 PGS，外挂的和文件内的都可以显示。外挂的 ASS/SSA 完整显示特效，文件内的 ASS 以简化的方式显示。视频旁的 .srt、.vtt、.ass、.ssa、.sup 自动列出，不是 UTF-8 的文字字幕按 GB18030 读取。一次显示一条字幕。
  • 布局：控制栏和面板与 App 的播放器相同，手机浏览器中是手机布局。有章节列表、进度条上的章节标记、剧集列表，以及视频信息和影片信息面板。
  • 画面：浏览器直接播放时，可以选择适应、填充或拉伸，有「裁切填满」按钮和画中画，Safari 中还可以 AirPlay；在页面中解码时没有这些。
  • 倍速：浏览器播放时 0.25 至 3 倍，在页面中解码时最高 2 倍。
  • 全屏：双击画面或按 F。手机上全屏时转为横屏；iPhone 上在页面中解码的视频也能全屏。
  • 按键：空格或 K 暂停，← → 快退快进 5 秒（按住 Shift 为 10 秒），↑ ↓ 音量，M 静音，F 全屏，N 和 P 下一个和上一个，A 和 C 切换音轨和字幕，Esc 退出。手机上双击画面左右两侧快退快进 10 秒。
  • 进度条末尾的时间可以在总时长和剩余时间之间切换。用 HTTPS 打开的网页，播放时屏幕保持常亮。
用 HTTPS 打开

网页通过 WebCodecs 使用硬件解码需要安全上下文，例如 HTTPS 或本机的 localhost、127.0.0.1；还要浏览器、设备和视频编码支持。普通 http://局域网地址 不提供这种能力。浏览器自己的播放器仍可能使用硬件解码，前提是它支持视频和声音，但不保证所有 4K、HDR 视频都能流畅播放。见在 Chrome 和 Edge 中使用硬件解码。

两种播放方式

播放器先看浏览器能不能直接播放这个视频：格式、视频和声音的编码都是浏览器支持的（MP4、WebM，Chrome 和 Edge 中还有 MKV），没有选择文件内的字幕，也不是杜比视界，就交给浏览器播放；否则在页面中解码。「视频信息」的「播放方式」显示当前是「浏览器自带播放器」还是「在网页里解码」。播放中选择文件内的字幕，或在 Safari 以外的浏览器中切换音轨，会改为在页面中解码，从同一位置继续。

用普通远程 HTTP 地址打开时，网页不能通过 WebCodecs 使用硬件解码，播放器会尝试把 4K 和 HDR 视频的画面交给浏览器自己的播放器；本机的 http://localhost 和 http://127.0.0.1 属于安全上下文，不受这个限制。浏览器的播放器只配合它自己能播的声音：AAC，Safari 和 Edge 中还有 AC-3 和 E-AC-3。声音是 DTS 或 TrueHD 的（例如蓝光 ISO），会改播同一语言的这类音轨并显示提示，这时不能换回原来的音轨；没有这样的音轨时，画面在页面中软件解码，4K 可能跳帧。是否能流畅播放还取决于设备、浏览器、编码和网络。

音乐

音乐播放

格式

  • 支持 MP3、AAC、FLAC、Apple Lossless（ALAC）和 APE，解码方式见下方「两种播放方式」；WAV、Opus、OGG 通常由浏览器播放，是否支持取决于浏览器。WavPack、TTA 等不能播放。
  • DSD：DSF 和 DSDIFF（包括 DST 压缩的）在页面中转为 PCM 播放。SACD ISO 播放立体声区的音轨，由服务器按音轨切分。
  • CUE 整轨按音轨播放。DTS-CD 抓轨（WAV 中的 DTS）解码后以立体声播放。
  • 杜比全景声：M4A 中的 E-AC-3 全景声在 Safari 和 Edge 中由系统的杜比解码器播放；其他浏览器播放其 5.1 声床，以立体声输出。
  • 高解析度音乐按浏览器的输出采样率播放。
  • 两种播放方式：电脑上的浏览器中，FLAC、MP3、M4A 中的 AAC-LC、Apple Lossless、APE、DSD、SACD、DTS 和 AC-3 在页面中解码，歌曲之间无缝衔接，但不能倍速；HE-AAC、Opus、OGG 和普通 PCM WAV 由浏览器播放，可以倍速，歌曲之间会有短暂停顿。手机和平板上 FLAC、MP3 和 AAC 由浏览器播放，锁屏后可以继续播放，歌曲之间会有短暂停顿，同一个文件中的 CUE 音轨除外。

播放器

  • 完整的播放器：封面、格式角标（DSD、Hi-Res、无损、声道、全景声），以及 MusicBrainz 的演职人员和发行信息。
  • 歌词：歌曲旁的 .lrc 文件，或歌曲自带的歌词；跟着播放高亮，点一行从这里播放。
  • 队列：下一首播放、移到最后、移除、清空；随机播放，列表循环和单曲循环。
  • 迷你播放器：收起后在页面底部，浏览其他页面时继续播放；锁屏和系统的媒体控制可以暂停和切歌。离开网页后停止。
  • 睡眠定时：15、30、45、60 分钟，或本首结束。由浏览器播放的歌曲可以 0.5 至 2 倍速，手机上按住为 2 倍速。
  • 媒体库首页的「继续收听」列出最近听过的专辑。

电脑和手机

  • 软件解码：在浏览器默认设置下用 http 局域网地址打开，或显卡不支持这种编码时，由处理器解码。近几年的电脑一般能流畅播放 1080p H.264；4K HEVC 和 AV1 优先使用硬件解码，软件解码能否流畅取决于处理器、视频码率和播放方式。
  • 硬件解码 HEVC（含 10-bit）：Intel 第 7 代酷睿及以后的核显、NVIDIA GTX 10 系列及以后、AMD RX 400 系列及以后，2017 年及以后的 Mac 和所有 Apple 芯片的 Mac。
  • 硬件解码 AV1：Intel 第 11 代酷睿及以后的核显、NVIDIA RTX 30 系列及以后、AMD 的多数 RX 6000 系列及以后，Apple M3 及以后的芯片。
  • Chrome 和 Edge 中的杜比视界 Profile 5：使用网页软件解码和 WebGPU，将画面转换为颜色正确的 SDR。1.2.0 改进了 Windows 上的 10-bit HEVC 解码和多线程性能，已在实机验证 Profile 5 流畅播放及正确颜色；这不代表所有设备都能流畅播放 4K。需要 WebGPU、多线程支持和安全上下文，性能不足时仍可能退回颜色不正确的兼容播放并显示提示。
  • 手机和平板：依靠硬件解码。iPhone 和 iPad 需要 iOS 或 iPadOS 16.4 及以后。

网页播放器做不到的

  • 浏览器不能把杜比、DTS、TrueHD 的源码输出到功放，也不能独占声卡或把 DSD 原样送到解码器；在页面中解码的声音以立体声输出。
  • 浏览器不能切换电视或显示器的帧率和 HDR 模式。
  • 没有蓝光和 DVD 的光碟菜单，DVD 和 VC-1 编码的视频不能播放（可以「复制链接」用其他播放器打开）。
  • 需要这些的，请用 CloudDrive2 App，连接同一个媒体服务器即可。

浏览器

在 Chrome 和 Edge 中使用硬件解码

网页的 WebCodecs 解码路径需要安全上下文：HTTPS 地址，或本机地址（localhost、127.0.0.1），并且浏览器、设备和编码要支持。普通 http://局域网地址 不能使用这条硬件解码路径；浏览器自带播放器支持的文件仍可由它播放，其他文件可能需要软件解码，4K HEVC 等视频可能跳帧。这一节说明缺少了什么、有哪些办法，以及怎样让 Chrome 和 Edge 把你的服务器地址当作安全地址。

多线程解码Chrome、Edge；还需跨源隔离没有：软件解码更慢
WebGPU✓没有：Chrome 和 Edge 中杜比视界 Profile 5 的颜色不对
播放时屏幕常亮✓没有

浏览器能直接播放的文件（例如 MP4 中的 H.264）由浏览器自己播放，不受影响。受影响的是在页面中解码的视频：浏览器不能直接播放的格式和声音，例如带 TrueHD 或 DTS 声音的 MKV、蓝光 ISO，以及 Chrome 和 Edge 中的杜比视界。软件解码一般能流畅播放 1080p H.264；4K HEVC 跟不上时，播放器会提示，并显示下面的设置方法。

普通远程 HTTP 页面不能通过 WebCodecs 使用硬件解码时，播放器会尝试把 4K 和 HDR 视频的画面交给浏览器自己的播放器；它仍可能使用系统的硬件解码，但取决于浏览器、设备和编码，不能保证流畅播放。这个播放器只配合它自己能播的声音：AAC，Safari 和 Edge 中还有 AC-3 和 E-AC-3。声音是 DTS 或 TrueHD 的（例如蓝光 ISO），会改播同一语言的这类音轨，并显示提示；没有这样的音轨时，画面仍在页面中软件解码，4K 可能跳帧。Safari 在支持的设备上还能直接播放杜比视界，但 HDR、杜比视界和高码率视频的效果仍取决于设备与网络。HTTPS 或本机安全地址是使用网页解码路径的推荐方式。

三种办法

  • 启用 CloudDrive2 自带的 HTTPS（推荐）：在网页管理界面的「设置 → Web 服务器」中启用 HTTPS（默认端口 19799）并配置证书。证书要与地址栏中的域名一致，浏览器才不会警告；有自己的域名的，可以使用 Let's Encrypt 等免费证书，或用 Nginx、Caddy、NAS 自带的反向代理提供 HTTPS。核心服务生成的自签名证书只对应 localhost、127.0.0.1 和 ::1，用局域网地址打开时浏览器会提示证书不受信任。从外网访问时请一定使用 HTTPS。
  • 在服务器本机上打开：在运行核心服务的电脑上用 http://localhost:19798 打开，本身就是安全地址。只适用于这一台电脑。
  • 把局域网地址设为安全地址：无法使用 HTTPS 时的备用方案。这个实验性设置不会加密 HTTP 连接。Chrome 和 Edge 都有这个设置，见下面的步骤；Android 手机、平板和电视盒子上的 Chrome 也有，步骤相同。

Safari（Mac、iPhone、iPad）没有这个设置；它的自带播放器能播放哪些格式，取决于系统和设备，见「HTTP 页面缺少什么」。需要网页解码或遇到跳帧提示时，请用 HTTPS 打开。iPhone 和 iPad 上的 Chrome 和 Edge 也没有这个设置，请使用 HTTPS；Safari 可作为原生播放的另一选择。Firefox 中请用 HTTPS 打开，或用 CloudDrive2 App 播放。

启用 CloudDrive2 自带的 HTTPS 服务

推荐优先使用核心服务自带的 HTTPS，不必修改浏览器实验性 flags，也不必另外部署反向代理。在自己的家庭网络中，没有受信任证书时也可以先生成自签名证书，确认服务器身份后按浏览器提示继续访问，并检查安全上下文是否可用。HTTPS 会加密传输；仅放行证书警告并不等于证书已获得系统信任。网页批量上传恢复任务时所需的安全连接，也可以使用这个 HTTPS 地址。

  1. 打开 Web 服务器设置

    进入网页管理界面的「设置 → Web 服务器设置」，打开「启用 HTTPS」。默认 HTTPS 端口为 19799；HTTP 的 19798 和 HTTPS 的 19799 是不同端口。

  2. 选择一种证书方式

    可以填写核心服务所在机器上的证书文件路径和私钥文件路径，也可以粘贴PEM 格式的证书内容和私钥内容。已有证书时，请使用与访问域名或 IP 地址匹配、且客户端浏览器信任的证书，然后点「应用」。

    家庭网络试用还可以点「生成自签名证书」：核心服务会生成证书、自动启用 HTTPS 并重启 Web 服务使其生效，当前网页连接可能短暂中断。之后如需修改端口，再点「应用」保存。

  3. 用新的 HTTPS 地址打开

    使用设置页显示的 HTTPS 地址，例如 https://192.168.1.20:19799；不要只把原来的 19798 地址改成 https。放行服务器防火墙中的 HTTPS 端口；Docker 使用桥接网络时，还要映射该端口，例如 19799:19799。如果宿主机映射了不同端口，地址栏应使用宿主机端口。

  4. 确认浏览器能力可用

    重新登录新的 HTTPS 地址并打开播放器。需要检查时，在浏览器控制台输入 window.isSecureContext，结果应为 true；WebCodecs 还可检查 typeof VideoDecoder !== 'undefined'。这表示浏览器接口可用，能否硬件解码仍取决于设备、浏览器和视频编码。

自签名证书与浏览器提示

内置生成器的证书只包含 localhost、127.0.0.1 和 ::1，不会自动加入你的局域网 IP 或域名，也不会自动获得浏览器信任，因此用局域网地址访问通常会有证书警告。确认地址确实属于自己的服务器后，可按浏览器允许的方式处理证书信任或继续访问，并以上面的安全上下文检查为准；不要把“能打开 HTTPS 页面”当作所有浏览器能力都已启用。长期使用或外网访问，建议配置名称匹配且受信任的证书，也可继续使用已有的 HTTPS 反向代理。

从 HTTP 切换到 HTTPS 属于切换网站来源：可能需要重新登录，并重新选择待续传的本地文件或目录；上传恢复能力还取决于浏览器对文件访问接口的支持。

备用方案：在 Chrome 和 Edge 中设置实验性 flag

  1. 记下网页的地址

    记下地址栏中网页管理界面的地址，只要开头到端口号的部分，例如 http://192.168.1.20:19798：包括 http:// 和端口号，不包括后面的 /?page=…。播放器的提示中显示的就是这个地址。

  2. 打开浏览器的设置项

    在地址栏中输入下面的地址并回车。网页不能替你打开浏览器自己的设置页，所以要复制后粘贴到地址栏；播放器的提示中有「复制设置地址」按钮。

    chrome://flags/#unsafely-treat-insecure-origin-as-secure
    edge://flags/#unsafely-treat-insecure-origin-as-secure

    第一行用于 Chrome，第二行用于 Edge。页面会高亮名为 Insecure origins treated as secure 的一项。

  3. 填入地址并启用

    在这一项的文本框中填入第 1 步的地址。用多个地址访问同一台服务器的（例如 IP 地址和主机名，或另一台服务器），用英文逗号分开：http://192.168.1.20:19798,http://nas.local:19798。然后把右边的选项改为 Enabled。

  4. 重启浏览器

    点页面底部的 Relaunch（Edge 中为「重启」）。浏览器会关闭所有窗口后重新打开，之前打开的标签页会恢复。

  5. 检查是否生效

    重新打开网页管理界面并播放，不再显示「这个网页不是用 HTTPS 打开的」。也可以按 F12 打开开发者工具，在「控制台」中输入 isSecureContext 并回车，显示 true 就是已经生效。

设置后仍然是软件解码

  • 地址要完全一致：http 和 https、IP 地址和主机名、端口号，都要与地址栏中的一样。服务器的 IP 地址变了（例如路由器重新分配），要重新添加；可以在路由器上为服务器固定 IP 地址。
  • 打开图形加速：Chrome 在「设置 → 系统」中打开「使用图形加速功能（如果可用）」；Edge 在「设置 → 系统和性能」中打开图形加速。改后要重启浏览器。
  • 看浏览器的 GPU 页面：打开 chrome://gpu 或 edge://gpu，「Video Decode」一行应为 Hardware accelerated。
  • HEVC：Chrome 107 起在 Windows、macOS 和 Android 上用显卡解码 HEVC；Windows 上的 Edge 还需要安装微软商店中的「HEVC 视频扩展」。
  • 显卡不支持这种编码：例如较老的显卡不支持 HEVC 10-bit 或 AV1，这时浏览器仍用软件解码，请用 CloudDrive2 App 播放。
  • 公司或学校管理的电脑：管理员可能禁用了 flags，可以请管理员用下面的策略设置。

用策略设置（多台电脑）

Chrome 和 Edge 都有策略 OverrideSecurityRestrictionsOnInsecureOrigin，作用与上面的设置相同，适合一次设置多台电脑。设置了策略后，flags 中的这一项不再起作用。Windows 上用管理员身份打开命令提示符：

reg add "HKLM\SOFTWARE\Policies\Google\Chrome\OverrideSecurityRestrictionsOnInsecureOrigin" /v 1 /t REG_SZ /d "http://192.168.1.20:19798" /f
reg add "HKLM\SOFTWARE\Policies\Microsoft\Edge\OverrideSecurityRestrictionsOnInsecureOrigin" /v 1 /t REG_SZ /d "http://192.168.1.20:19798" /f

第二个地址用名称 2，依此类推。Linux 上在 /etc/opt/chrome/policies/managed/（Edge 为 /etc/opt/edge/policies/managed/）中新建一个 JSON 文件：

{ "OverrideSecurityRestrictionsOnInsecureOrigin": ["http://192.168.1.20:19798"] }

重启浏览器后，在 chrome://policy 或 edge://policy 中可以看到这条策略。macOS 上的策略需要用配置描述文件安装，个人电脑用上面的 flags 即可。

这个设置不加密连接

它只是让浏览器把这个地址当作安全地址，连接本身仍然是不加密的 HTTP：同一网络中的设备可以看到传输的内容，包括登录信息。只添加你自己家庭网络中的服务器地址，不要添加公共网络或别人的地址；从外网访问请用 HTTPS。

常见问题

常见问题

播放时提示「这个网页不是用 HTTPS 打开的」

用 http://局域网地址 打开网页时，浏览器不让网页使用硬件解码，声音不是浏览器自己能播的 4K 视频在页面中解码，跟不上。请用 HTTPS 打开，或让 Chrome 和 Edge 把这个地址当作安全地址，也可以改用 Safari，见在 Chrome 和 Edge 中使用硬件解码。

有的视频不能播放

DVD、VC-1、RMVB、WMV 等浏览器无法播放，页面会显示「复制链接」和「下载」，可以用 VLC、IINA、PotPlayer 或 Infuse 播放，也可以用 CloudDrive2 App 播放。浏览器版本太旧时，页面中解码也不能使用，见浏览器和电脑的要求。

4K 视频卡顿或跳帧

先确认显卡支持这种编码的硬件解码，并用 HTTPS 或安全地址打开网页（Safari 中多数视频用 http 地址也可以），见浏览器和电脑的要求。在页面中解码的杜比视界（Chrome 和 Edge 中的 Profile 5）由处理器解码，4K 需要性能较强的电脑。还要看网盘的速度：视频由核心服务从网盘读取，网盘的下载速度要高于视频的码率。

排查网页软件解码卡顿时，请先关闭开发者工具并重新加载页面，再测试播放速度；打开开发者工具可能使解码性能下降。普通局域网 HTTP 地址可按Chrome / Edge 设置说明将指定服务器设为安全来源，外网访问请使用 HTTPS。

没有声音，或声音是立体声

Safari 要在点击之后才允许网页出声；页面提示声音暂停时，点一下页面即可。在页面中解码的声音以立体声输出，浏览器也不能把杜比、DTS 的源码输出到功放；要输出多声道或源码，请用 CloudDrive2 App。

播放进度会同步到其他设备吗？

从媒体库播放时会：进度和已看与媒体服务器同步，其他设备和 CloudDrive2 App 都能看到。从文件管理播放时，位置只记在这个浏览器中。
