The first thing to do after installing

Open it in a browser

http://<host IP>:19798

The CloudDrive2 management interface runs on that port — the same on Windows, Linux, macOS, Android and inside Docker. On the machine itself, use http://localhost:19798. Use a recent version of Edge, Chrome, Safari or Firefox. Internet Explorer is not supported.

Installing and running

Pick your system

This section covers installing the core as a background service — on a computer, a NAS or a router. The apps for phones, TVs and headsets carry the same core and come from their own stores; see "Install the apps" below.

Windows
  1. Download the CloudDrive2 installer from our website.
  2. Run the installer and follow the on-screen prompts.
  3. When it finishes, a CloudDrive2 shortcut appears on your desktop. Double-click it, or just open http://localhost:19798 in a browser.
Linux, generic
  1. Check that your kernel supports FUSE by looking for the /dev/fuse device. Without FUSE support you cannot mount clouds as local directories.
  2. To run CloudDrive2 as a non-root user, install fuse3 the way your distribution's manual describes, confirm that the fusermount3 command runs, then edit /etc/fuse.conf and remove the leading # from the user_allow_other line.
  3. Download the archive for your CPU architecture from our website.
  4. Open a terminal and change into the directory holding the archive.
  5. Extract it: 
    tar zxvf clouddrive-2-linux-$ARCH-$VERSION.tgz
  6. Change into the extracted directory and run: 
    ./clouddrive
  7. You can add clouddrive to your system's startup items or register it as a system service. See your distribution's documentation for how.
Arch Linux
  1. Arch Linux and its derivatives can install from the AUR package or a third-party repository: 
    yay -Syu clouddrive
  2. Start clouddrive with systemd and enable it at boot: 
    # as root
systemctl enable --now clouddrive.service

# as your user
systemctl --user enable --now clouddrive.service
  3. Check that clouddrive is running: 
    # as root
systemctl status clouddrive.service

# as your user
systemctl --user status clouddrive.service
  4. Open the management interface in your default browser: 
    # recommended
xdg-open http://localhost:19798

# IPv4
xdg-open http://127.0.0.1:19798

# IPv6
xdg-open http://[::]:19798
  5. If the page loads slowly or stutters, open it in your browser's private or incognito window.
  6. Mounting a local disk after signing in asks for a UID and GID: 
    # current user
id -u
id -g

# another user
id -u username
id -g username
  7. The AUR package's local disk mount point: /media/clouddrive.
  8. The AUR package's WebDAV mount point: /media/clouddrive-dav. This one needs the davfs2 package.
  9. Put your WebDAV username and password into /etc/davfs2/secrets, for example: 
    cat << EOF | sudo tee -a /etc/davfs2/secrets
# personal webdav, application password
/media/clouddrive-dav user@email.com  mypassword
EOF
  10. Start clouddrive-dav with systemd and enable it at boot (as root): 
    systemctl enable --now clouddrive-dav.service
  11. Check that clouddrive-dav is running (as root): 
    systemctl status clouddrive-dav.service
macOS

With Homebrew (recommended)

  1. Make sure Homebrew is installed.
  2. Install macFUSE before running CloudDrive2, and grant it permission in System Settings when prompted. Homebrew can install it too: 
    brew install --cask macfuse
  3. Install CloudDrive2: 
    brew tap cloud-fs/clouddrive2
brew install clouddrive2
  4. Start CloudDrive2: 
    brew services start clouddrive2
    This creates a background service that starts again the next time you log in.
  5. Open http://localhost:19798 in a browser to reach the management interface.
  6. Stop CloudDrive2: 
    brew services stop clouddrive2
  7. Uninstall CloudDrive2: 
    brew services stop clouddrive2
brew uninstall clouddrive2
  8. Upgrade CloudDrive2: 
    brew services stop clouddrive2
brew update
brew upgrade clouddrive2
brew services start clouddrive2

Manual install

  1. Install macFUSE first and grant it permission when prompted.
  2. Download the archive for your CPU architecture from our website.
  3. Open a terminal and change into the directory holding the archive.
  4. Extract it: 
    tar zxvf clouddrive-2-macos-$ARCH-$VERSION.tgz
  5. Change into the extracted directory and run: 
    ./clouddrive
  6. You can add clouddrive to your login items or register it as a system service. See the macOS documentation for how.

For what differs between the Mac App Store build and the direct download, see CloudDrive2 for macOS.

Android
  1. Download the .apk, install it and open it.
  2. An un-rooted device cannot mount clouds into the local file system. Everything else still works, including multi-cloud backup and the WebDAV service.
Docker, NAS, Synology and QNAP

To run it in a container on a NAS or server, the image is cloudnas/clouddrive2. Shared mounts have to be enabled on the host first; the full steps and a configuration you can copy as it stands are in the Docker deployment guide.

The fnOS fpk package and the third-party Synology and QNAP packages are on the download page.

Getting started

Once you are in the console

Register, sign in, connect your first cloud. Three steps.

  1. Register

    The first time you run CloudDrive2, click Register in the top right corner and enter your email address and a password. A verification email is sent to that address; follow the instructions in it, and once verified you are taken to the sign-in page.

  2. Sign in

    Click Sign in in the top right corner and enter the same email address and password. If your account is verified, you land on the CloudDrive2 home page.

  3. Add cloud storage

    Choose Add Cloud Storage, pick your provider from the list, enter your account details and press OK. CloudDrive2 verifies the account, and once it passes, that cloud storage appears in CloudDrive2.

Day to day

A few things you will need later

Managing files
  1. Inside CloudDrive2 you can work on the files in your cloud storage directly: upload, download, delete, move and so on.
  2. If you mount a cloud as a local drive, you can work on its files exactly like local ones — in Explorer, in Finder or in any application.
Deleting cannot be undone

Deleting a file in CloudDrive2 deletes the real file in your cloud storage. Once it is gone it may not be recoverable, so check before you delete.

WebDAV service

CloudDrive2 serves every cloud you have connected back out as a single WebDAV service, so any software that speaks WebDAV can connect to it.

  • Server address: http://<ip>:19798/dav
  • Username: the email address you sign in to CloudDrive2 with. The local part alone works too — everything before the @.
  • Password: your CloudDrive2 password.

More about the WebDAV service

Forgotten password

The account information stored in the cloud is encrypted with your own password, and we do not keep a copy of that password. If you forget it, click Reset on the sign-in screen and follow the prompts.

A reset wipes your stored cloud accounts

Resetting clears the cloud storage account information saved in the cloud and resets your password, so you will need to add your cloud storage again. Your membership plan is not affected.
