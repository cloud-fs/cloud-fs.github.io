Media library

Choose folders in your cloud storage, and the CloudDrive2 app turns the films, shows, music and books in them into libraries with posters, plots and cast. No Emby, Jellyfin or Plex server is needed: NFO files and artwork already in the folders come first, and what they leave out can be looked up on TMDB and other sites; if you already run an Emby or Jellyfin server, you can import its libraries. The results stay on your own devices, and can sync across them through your own cloud storage.

Types

Five kinds of library

A library is one or more folders. They can be on any cloud storage, WebDAV server, NAS or local disk that CloudDrive2 can list. Different libraries' folders may overlap.

Where libraries appear

Libraries appear in the app's Media interface as "CloudDrive Libraries", next to Emby and Jellyfin servers. Choose Media under Settings → Interface to start the app on the poster wall.

  • Home: Featured, Continue Watching, Next Up, Continue Listening, Continue Reading, and a "Latest" row for each library. A library being scanned or synced shows its state, such as Scanning, Identifying or Syncing; one that another device scans shows Elsewhere or Waiting (see One device scans a library).
  • Featured: a carousel at the top of Home with titles from Continue Watching, Next Up and the newest in each library. Titles of a locked private library, and titles above parental control's rating limit while locked, are never featured.
  • Search: translated and alternative titles are found too, and accents and Traditional or Simplified Chinese don't matter. A song is found once its album's page has been opened.
  • Favorites: kept apart from library data, so Clear library data and a rescan keep them, and they sync with Sync libraries across devices.

Devices

The CloudDrive2 apps on iPhone, iPad, Mac, Windows PCs, Apple TV, Apple Vision Pro, Android phones, tablets and TVs, and Meta Quest. Each device builds its libraries itself; no server has to stay on.

The features are the same on every device, with these differences: the Emby API isn't on Meta Quest; Apple TV can't import from Emby or Jellyfin, but shows libraries another device imported; on Apple TV and Android TV, person pages leave out the links and Scan again has no custom interval; on Apple TV, Edit metadata… changes text only, and on Android TV its pictures come only from your cloud storage; Android has no video-track picker, and no picking several titles or right-click menu. Smaller differences are noted where they matter.

The core service's web interface doesn't show libraries. It has a Titles to Confirm page where you can confirm, in a browser, the titles the automatic match wasn't sure about. See Confirming on the web.

Identification

These settings stay on the device and don't sync.

  • Look up titles on TMDB: off by default. When on, titles without an NFO get their poster, plot and cast from TMDB. You don't need your own API key.
  • Look up anime on Bangumi: on by default; works while TMDB lookup is on.
  • Look up music on MusicBrainz: off by default. Finds an album's year and a missing cover, the exact release and its credits, and artist pages take their biography and photo from Wikipedia and Wikimedia Commons.
  • Look up books on Open Library: off by default. Finds a book's year and a missing cover; author pages show a biography from Open Library and Wikipedia.
  • AI identification: off by default. An AI service and model you choose help identify the films, albums and books the rules can't; see AI identification.
  • API address: api.tmdb.org by default, which is reachable from mainland China. Or api.themoviedb.org (may not be reachable from mainland China), or your own https address, such as a reverse proxy.
  • Image address: image.tmdb.org by default, or your own.

Import

Import from Emby or Jellyfin

When an Emby or Jellyfin server's media is on your cloud storage (mounted through CloudDrive2, for example), you can import the server's libraries: the titles' text, pictures, media info, your watch history and the people are read from the server, so no folder is scanned and nothing is scraped again, and the titles play straight from your cloud storage. The import only reads the server; it changes nothing there.

Only servers whose media files are themselves on your cloud storage are supported. Libraries that point to their media with .strm files can't be imported yet.

How to import

  1. Sign in to the server under Media Servers first. Only a server administrator can read the libraries' folders.
  2. In Settings → Media Libraries, choose Import from Emby or Jellyfin…, then the server.
  3. The server's libraries are listed with each of their folders. A folder on this device's cloud storage shows "… plays directly from …"; one that isn't (the server's own disk or NAS) shows "… is not on this device's cloud storage" and is left out. The matching cloud folder comes from the CloudDrive2 companion plugin on the server, the same storage account, and the path mappings you set for the server under Media Servers.
  4. Tick the libraries, choose which people to import and which goes first when CloudDrive already has something, and choose Import. It runs in the background: you can close the window, and Settings → Media Libraries shows how far it has got. A library imported before shows Update; importing it again brings it up to date.

The server's movie libraries become film libraries, its TV libraries show libraries, and its other video libraries mixed libraries. Music and book libraries can't be imported yet.

When CloudDrive already has it

Chosen separately for titles and for people: The server's first (titles' default), CloudDrive's first, or Whichever has it; the newer when both do (people's default). An empty field never replaces a filled one, and nothing of CloudDrive's is deleted. Importing the same server again starts from the last choices; a library's title choice can also be changed in its editor, on the "Imported from …" row, without reading the server again.

What comes along

  • Films' and shows' names, original titles, plots, taglines, genres, tags, studios, age ratings, ratings and premiere dates; posters, logos, banners, thumbs and every backdrop, fetched from the server when shown.
  • A show's seasons and episodes, each episode's name, plot, numbers, runtime and air date.
  • The media info the server read: resolution, HDR and Dolby Vision, audio tracks (Atmos and DTS:X included) and subtitles. Files the server couldn't read, some ISOs for example, are detected by the app in the background.
  • Your played state, resume points and favourites on the server (the signed-in user's); a newer one on the device is kept.
  • People: People in these libraries with a biography or photo (the default), Everyone in these libraries, Everyone on the server, or No one. Their biographies, birth and death dates, birthplaces, photos and up to six backdrops, their tags and one-line description. Photos are downloaded to the device.

After the import

  • An imported library is read from the server: no folder is scanned and nothing is looked up online, and Home and the library page show "Reading from <server> · N titles read". Each rescan reads the server again, and titles the server no longer lists leave.
  • With Sync libraries across devices and Sync scanned data on, an imported library reaches your other devices, which use what the importing device read; people's biographies, photos and first three backdrops travel too. On a device not signed in to that server, a server picture that can't load gives way to another.
  • Apple TV doesn't import, but shows the libraries another device imported.

Recognition

How videos are recognized

Building a video library reads only the names of folders and files; no video file is opened. The usual ways of naming are understood, including long names from download sites and release groups, fansub names, episodes in Chinese numerals, Blu-ray and DVD folders, films split into parts, and sets of discs, so files don't need renaming first.

Files that are not titles

  • Extras and trailers belong to their title, such as trailers and featurettes folders, files whose names end in -trailer, and fansub [NCOP] and [NCED] files.
  • NAS and system folders are not read, such as @eaDir, #recycle and $RECYCLE.BIN.
  • Videos with words such as test, sample or demo in their names are treated as test clips and never looked up.
  • Several files of one film in a library become one title, with each file as a version to choose on its page.

Naming the entry yourself

{tmdbid=123}, [tmdb-123], (imdb-tt0113277) or MoviePilot's {[tmdbid=123;type=tv;s=2]} in a file or folder name names the TMDB or IMDb entry, and nothing is searched. When a title is wrong, you can also pick the entry in Identify…, or fix many files at once with recognition words.

Video files

mkv, mp4, m4v, mov, avi, wmv, flv, webm, mpg, mpeg, m2ts, mts, ts, vob, rmvb, rm, 3gp, ogv, iso.

Scraping

Scraping and matching

Once a title and year are read, the title's details and pictures come from TMDB, and anime is also looked up on Bangumi. A title that can't be matched with certainty goes to Needs review and plays as usual until you confirm it; an entry you pick in Identify… is never replaced by an automatic match.

The NFO and artwork you have

NFO files, posters, backdrops, logos and season posters written by Kodi, Emby, Jellyfin, tinyMediaManager and similar tools are read. When an NFO has a TMDB or IMDb id, the entry is fetched by that id and nothing is searched.

The NFO and artwork in the folder come first, and TMDB fills only what they leave out; with the library's Prefer online info on, it is the other way round. What you save with Edit metadata… always comes first.

What comes from TMDB

Title, plot, genres, rating, poster and backdrop, cast and directors, each season and episode, box sets, and the certifications used by parental control. The language they show in is the library's Metadata language.

Anime

Anime named the fansub way is looked up on Bangumi first, and the bangumi-data table gives the TMDB season and episode it maps to, so anime whose seasons TMDB divides differently still lands on the right episode.

When titles are looked up

  • In the background, titles on screen first. Phones and TVs look up only while the app is in front.
  • Titles in Needs review or Not found are looked up again after 7 days, or when their name changes; Look up unidentified titles again, in the library's settings, does it at once.
  • With Sync scanned data across devices on, the results travel to your other devices, which don't look those titles up again.

Confirming

Needs review and Identify

Titles that automatic matching can't decide go to Needs review, and play from their files as usual until you confirm them. Problems that media info detection finds are listed there too: files that can't be read, and files whose length differs a lot from the matched title.

Identify…

Every title page has Identify…: pick one of up to 5 candidates, search by title and year, mark it Not on TMDB, or Look Up Automatically. When the identification is an automatic match, Keep This Match makes it your choice.

Your choice stays, and automatic matching never overwrites it; with sync on, your other devices take it too. Identify… works even with the library's Look up online off.

Identify Album and Identify Book

Identify Album on an album page and Identify Book on a book page pick the right MusicBrainz or Open Library entry, which fills in a missing year and cover. The choice syncs with the library.

AI identification

For films, albums and books the rules can't identify, an AI model can suggest what to search for. Under Settings → Media Libraries → Identification → AI identification, choose the service, the model and the API key (the same key AI subtitles use), and the libraries the model reads. Private libraries and libraries with Look up online off can't be chosen.

  • The model reads an item's path below its library folder and what was read from its files, and gives search terms only. TMDB, MusicBrainz and Open Library are then searched as usual, and the rules above decide.
  • Once on, the model is asked in the background about items not identified yet. Each item's answer is kept on the device; at most 1,000 calls a day.
  • Ask AI in Identify… shows the model's answer and its evidence. Nothing is saved until you pick a result.

Confirming on the web

The core service's web interface has a Titles to Confirm page, handy for clearing in a computer's browser the titles a TV has piled up.

  • At least one device needs Sync libraries across devices on. The page reads the review lists your devices upload to the CloudDrive2 Sync folder.
  • Pick a candidate, or paste a TMDB link or ID; the page has no title search.
  • Your devices take the choice the next time they sync.
  • Titles of a private library show after you unlock with the PIN.

Recognition words

Recognition words

Recognition words rewrite this library's file and folder names before they are read: fix a season's numbering, swap a title for the one you want, remove an ad prefix. The format is MoviePilot's custom recognition words, so existing lists paste straight in. One rule per line, applied in order; a line starting with # is a note.

# Delete words
国语中字
# Replace ((?i) ignores case)
(?i)Kimetsu no Yaiba => 鬼灭之刃
# Shift the episode numbers between two words
第 <> 集 >> EP+12
# Replace, then shift
Apotheosis.S02 => Apotheosis S01 && S01 <> 2160p >> EP+52
# Point a name at a TMDB title, optionally a season and episode
斗罗大陆 => 斗罗大陆{[tmdbid=99025;type=tv]}
  • =>, &&, <> and >> need a space on each side. When shifting episodes, either of the two anchor words may be empty.
  • Rules are regular expressions, matched against the name as it is, extension included; they are case-sensitive unless they start with (?i).
  • A shift changes every number between the two words. The expression can use EP, whole numbers and + − × ÷. Leading zeros are kept (05 plus 12 is 17), and Chinese numerals stay Chinese.
  • {[…]} takes tmdbid, imdbid, type (movie or tv), s (season) and e (episode).
  • The first 1,000 lines are read, each up to 1,000 characters.
  • Words apply only inside this library. The file browser, the player and subtitles still see the real names, and no file is renamed.
  • The editor checks each line, for example "Line 4 isn't used: …". Try a name shows the rewritten name, which lines changed it, and the title, year, season and episode read from it.
  • After an edit the library is read again; NFO details and watch progress are kept.
  • Export saves <library> recognition words.txt (UTF-8). Import reads UTF-8 or GB18030 files and asks whether to Add to the end (skipping lines already there) or Replace. On a TV, type the whole text on a phone.
  • Words sync with the library; the newest edit wins.

Shelves

Shelves

Shelves appear as a row of buttons at the top of a library page: All first, then each shelf with its count. The row shows only when at least two shelves hold titles. The rules use MoviePilot's category.yaml format, so an existing file pastes straight in. Each title goes on the first shelf whose conditions all hold; a shelf without conditions takes every title still left.

Media info

Media info

Media info is what a video file itself holds: resolution, frame rate, HDR, codecs, audio and subtitle tracks. It feeds the title page's media info card, the poster badges and the Picture and sound filters. Detecting it reads only a small part at the start of a file; whole files are never downloaded.

Where it comes from

  • From the file name: every title first gets what its name says about resolution, HDR, codecs and audio (2160p, DV, Atmos…).
  • From the NFO: the NFO's <streamdetails>.
  • Detect media info: reads the start of the file. MKV, MP4, TS and M2TS; a 2-hour film usually costs 128–320 KB. Blu-ray ISOs and BDMV folders are read from their playlists.
  • While playing: a few seconds into a library video, what the player found is saved.

It reads codecs, resolution, frame rate, HDR10, HDR10+, HLG and Dolby Vision, Dolby Atmos, DTS-HD MA and DTS:X, and the audio and subtitle languages. Results are kept by the file's size and modified time, and detected again when the file changes.

Where it is used

Media info drives the 4K, Dolby Vision, HDR and Atmos badges on posters (solid when detected, outlined when only the file name says so), the Picture and sound filters, the choice of the version best on this device when a film has several, and the Needs review list of files that can't be read or whose length doesn't match. With Save info and artwork beside the media on, detected tracks also go into the NFO.

Detected while identifying

Each video library's Detect media info while identifying is on by default: the device that scans the library reads the start of each video file as its title is identified, newest titles first, usually about 256 KB a file. With Sync scanned data on, the results travel, and your other devices don't read the files again.

Detect media info in the background

For the libraries that don't detect media info while identifying. Under Settings → Media Libraries → Scanning & storage; off by default, and for this device only. It reads the start of each video file, one at a time and slowly: after each file it waits the Wait between files time (2 s on clouds by default), and it pauses while a video plays.

People and box sets

People, box sets and editing

Cast, artists and authors have pages of their own; the films of one box set can be browsed together; and a film's or show's details can be edited by hand.

Person pages

  • Cast and directors: biography, photo and links from TMDB, in the library's metadata language; the page lists the titles in your libraries that name them.
  • Artists: biography and photo from Wikipedia and Wikimedia Commons, through the links MusicBrainz gives.
  • Authors: a biography from Open Library and Wikipedia.
  • One person is one record whether an NFO, TMDB or a music or book credit names them, and any of their names finds them.
  • Names, biographies and photos other apps send through the Emby API come first.

Box sets

TMDB's collection, or the NFO's <set>, puts a film in a box set. Box sets with at least two films in the library appear under Collections in the shelf row.

Edit metadata

Film and show pages have Edit metadata… for the title, plot, genres, cast, pictures and more. Edits are saved as the NFO file and pictures in the film's folder, so other apps and your other devices read them too; only what you changed is rewritten, and what other apps wrote stays. Your edits outrank online info, and Prefer online info never replaces them. Apple TV can't change pictures.

Playback

Skip intro and ending

Playing an episode of a library's show, you can set in the player where the season's intro ends and where its ending starts. They hold for every episode of that season, and reach your other devices with Sync libraries across devices.

Setting them

  • While an episode of a library's show plays, open Intro and Ending in the player and press Set to Now where the intro ends or the ending starts.
  • The intro is counted from each episode's start and the ending back from its end, so episodes of different lengths share them.
  • The Skip intro and ending switch is for this device only and on by default; off, nothing is skipped and the times stay.

While playing

  • An episode played from the start skips the intro; reaching the ending's start plays the next episode, and the episode counts as watched.
  • Seeking into the intro or the ending yourself plays it.

Devices

Mac, iPhone, iPad, Apple TV, Apple Vision Pro (in a window and in the immersive player), Android phones, tablets and TVs, Meta Quest, and Windows PCs.

Writing to folders

  • Copies for Infuse: also writes the poster and backdrop under the names Infuse reads (<file name>.jpg, <file name>-fanart.jpg).

NFO files use Kodi's format, in the device's display language: title, original title, rating, plot, tagline, runtime, TMDB and IMDb ids, genres, directors, premiere date, cast and more, with <lockdata> so Emby and Jellyfin don't rewrite them. An album gets files only when MusicBrainz has decided it and it has a folder of its own; no cover is written when the folder already has any picture. A book gets files only when Open Library has decided it. Music libraries need Look up music on MusicBrainz, and book libraries Look up books on Open Library.

Other people's files are left alone

  • An NFO written by CloudDrive2 carries a marker on its second line. If a folder already has another tool's NFO, nothing is written for that title. If it already has a poster, backdrop or other image in a role, that image is skipped.
  • The exception: in a video library with both Prefer online info and Save info and artwork beside the media on, after a confirmation, other apps' .nfo files and pictures are renamed (with .bak added) and replaced with TMDB's. Nothing is deleted. Music and book libraries have no such exception.
  • When a title's identity changes, only files CloudDrive2 wrote itself, and nobody changed since, are replaced.
  • A file you delete isn't written again unless you choose Check again.
  • For a private library, a warning comes first: titles, plot and posters are saved as ordinary files that anyone who can open the folders, and the storage provider, can see. Nothing is written while it is locked.

How fast

Before it starts, you see an estimate: about 3 files per film, 3 per show plus 2 per episode, and 2 more with Infuse copies. Files are uploaded one at a time, at least 1 second apart. When the storage asks to slow down, writing continues 15 minutes later.

Covers

Library data

How information is stored and kept up to date

Each device builds its libraries itself: it lists the folders through its own CloudDrive2 and writes the results into the device's library database, one per CloudDrive account. It is kept apart from the app's cache, so clearing the cache doesn't delete it; after a restart or an app update the libraries open at once, and files already read aren't read again. The rules are the same on every platform, so the same folders give the same result on every device. Library settings, identifications and hearts can sync; with Sync scanned data, so can what a device has read and looked up, and the posters and covers: a library scanned completely on one device is ready on the others.

When a library is scanned again

  • A library scanned completely isn't scanned again by itself. Scan again in the library's settings sets an interval for automatic scans, and Scan now or Scan this folder scans at once.
  • A first scan that was stopped goes on from where it stopped at the next start, until it is complete.

Picking up new files by itself

With the Core Pro feature file change notifications, files added, deleted or renamed through this device's CloudDrive2 (the app, the web interface, WebDAV, the mounted drive) usually reach the library within seconds, with no rescan.

115, Baidu Netdisk and 123 Pan update a folder's modified time when its contents change, so files added elsewhere are found on the next read. Changes made on other storage by other devices, or by the storage's own app, appear on Refresh, or when you use Scan this folder or Scan now.

On this device

Settings → Media Libraries → Scanning & storage shows the space library data and pictures use. Picture limit offers 500 MB, 1 GB, 2 GB, 5 GB, 10 GB, 50 GB, 100 GB and Unlimited. Clear library data deletes what was read, the details and the pictures, then reads the libraries again; the libraries, identifications and watch progress stay.

Offline

When a site can't be reached, cached information is used. What the library database holds shows at once when the app starts, and storage or folders that can't be reached never empty a library.

Keep the cloud from limiting your account

A cloud storage can limit an account that lists folders too fast or downloads too much. CloudDrive2 scans carefully to avoid this: it lists folders at the library's Listing speed, 2 a second by default, with at most 3 at a time; it reads music tags at most one file a second per storage account; and to detect media info it reads only the start of a file, usually a few hundred KB.

These limits apply on each device. When several devices scan the same storage account, their requests add up, and CloudDrive2 can't prevent that. So it's best not to scan libraries in the same storage account on more than one device. With both Sync libraries across devices and Sync scanned data across devices on, each library is scanned by one device and the others use its results; see One device scans a library.

We also suggest keeping media files and synced data in different storage accounts, so scanning the libraries and syncing their data don't send requests to the same account. For example, keep media files on 115 and the CloudDrive2 Sync folder on 123 Pan.

Sync

Sync libraries across devices

Create a library or choose an identification on one device, and your other devices get the same. Turn on Settings → Media Libraries → Sync → Sync libraries across devices. It is an App Pro feature, off by default, and uses the same CloudDrive2 Sync folder as progress sync: whichever you turn on first picks the storage, and the other uses it without asking. We suggest a storage account other than the one that holds your media files; see Keep the cloud from limiting your account. The data stays in your own cloud storage and never passes through CloudDrive's servers.

What syncs

  • Each library's settings, including its folders, recognition words, shelves and the device that scans it; deleting a library syncs too.
  • The PIN check (not the PIN itself).
  • The identifications of titles, albums and books, your choices included.
  • Favorites, and each season's intro and ending times.
  • The Needs review list, for the web page.

What doesn't

  • Library data and pictures: these sync with Sync scanned data across devices, a switch of its own.
  • Choices for this device only, such as the online info switches, Listing speed, Picture limit and parental control.
  • Watch progress and watched marks: these sync with progress sync.

Sync

Sync scanned data across devices

A device that has listed your folders, read the files and looked titles up can share the results, so your other devices don't read and look them up again. A library scanned completely on one device is ready on the others, and a new device shows a big library within minutes. Turn on Settings → Media Libraries → Sync → Sync scanned data across devices. It is an App Pro feature, off by default, and uses the same CloudDrive2 Sync folder as Sync libraries across devices. The data stays in your own cloud storage and never passes through CloudDrive's servers.

What a device shares

  • What it read from the files: NFO details, media info, music tags, cue sheets, SACD disc text and book metadata.
  • Each folder's result, and the list of titles of a library scanned completely. A device that takes the list shows the whole library at once, and reads what changed only when a change is found or you ask for a scan.
  • The results of online lookups, Needs review and Not found included, and the details of people.
  • Private libraries' data too: private only hides those libraries on the media screens and doesn't limit access to your storage.

What doesn't

  • Pictures: the picture packs below share them.
  • Each device's own choices, such as Picture limit and Keep files on this device.

When it syncs

A device reads when the app starts and when it comes back to the front after 10 minutes or more, and writes when a scan or a lookup pass ends with something new. Packs and pictures wait for Wi-Fi or Ethernet unless Sync over mobile data is on.

Turning it off

What was taken in stays on the device. You can also delete this device's packs and picture files from the storage.

Adding a device

Sign in to the same CloudDrive account, make sure the device reaches the storage holding CloudDrive2 Sync, and turn on Sync libraries across devices and Sync scanned data across devices. Library folders are saved as full CloudDrive2 paths, so the storage needs the same path on the new device. Libraries another device scanned completely are ready at once: a new iPad showed all the titles of a Mac's 7 video libraries in about a minute.

Sync first, then scan

When the app starts, when sync is turned on, and when a library is added, the device first takes in what your other devices scanned, then scans and identifies only what the packs don't hold. It waits at most 5 minutes, and scans as usual when offline or when the read fails.

Who can read the packs

The packs are compressed, not encrypted. They hold the titles' paths, what the NFO files say, what was read from the media files, and the answers of TMDB, MusicBrainz and the like. Anyone who can open that storage can read them, private libraries' data included.

One device scans a library

With both sync switches on, one device scans a library and the others wait for its results instead of each listing the same folders. The device that created the library scans it, unless another is chosen with Scan this library on this device in the library's settings.

  • While it scans, the scanning device uploads its pack at least every 10 minutes; the other devices show "Scanning on <device>" and take in what it finds as it goes.
  • If the scanning device uploads no pack for 30 minutes (switched off, offline), another device continues the scan, and nothing found so far is lost.
  • Scan now, Scan this folder and Refresh on this device always scan at once.
  • A book library scans in seconds, so each device scans its own.

Picture packs

Fetching posters one by one from cloud storage is slow. With Download picture packs on (it needs Sync scanned data), a device takes posters and covers from a few big files your other devices wrote, instead of one by one. It is on by default on phones, tablets, computers and Quest, and off on Android TV and Apple TV.

  • Devices that write packs: devices that hold the pictures, with Share pictures on (the default); they write only while another device asks.
  • What a pack holds: posters, season posters and covers; no backdrops or people's photos.
  • What a device downloads: pictures of the libraries it shows that it doesn't hold yet, newest titles first, until its Picture limit is 90% full. It waits for Wi-Fi or Ethernet and pauses while a video plays.
Large libraries take a while

For a large library, the first sync of scan data and pictures can take a long time, so please be patient. It runs in the background, and what is already shown can be used as usual.

Pictures are cached on this device and can take a lot of storage. Set Picture limit in Settings → Media Libraries → Scanning & storage to suit you: 1 GB by default, 500 MB to 100 GB, or Unlimited. Over the limit, the pictures not shown for the longest are deleted first.

Private

Private libraries and the PIN

A private library shows only after the PIN is entered. While locked, it and its titles are absent from every list, Home, Continue Watching, Needs review and count. There is one PIN per CloudDrive account, 4 to 8 digits, set under Settings → Media Libraries → Privacy & parental control.

  • Lock Again: 5 minutes after you leave the app by default, or when you leave it, or after 15 minutes or 1 hour. The app starts locked every time.
  • A private library starts with Look up online off, and its titles are never sent to the AI identification service.
  • Where another library's folders overlap a private library, the overlapping part is hidden there too while locked.
  • Forgot PIN…: the PIN can't be recovered. You can remove every private library and the PIN, then add them again; their folders and files stay.
The PIN doesn't encrypt anything

The PIN hides private libraries in the media screens. It doesn't restrict access: their folders can still be opened in the file browser and in the storage's own app. The sync file holds a check value for the PIN (PBKDF2-SHA256, 100,000 rounds), not the PIN itself, but a 4-digit PIN can be found by trying quickly, so don't use it as a password.

Parental control

Parental control

Parental control leaves only the libraries to browse on this device: opening Files, switching to the file manager or opening Settings needs a 4-digit parental code. Turn it on under Settings → Media Libraries → Privacy & parental control; it needs App Pro. The code stays on this device and doesn't sync; it is a different code from the private libraries' PIN.

While locked

  • While locked, Files, the file manager and Settings can't be opened, and Identify…, adding a library and deleting one ask for the code.
  • It locks at once when you leave the app or the screen sleeps; Auto-Lock can also lock it again after a time without use, Never by default.
  • Forgot code?: enter the password of the CloudDrive2 account signed in on this device; once it is confirmed, set a new code.

Highest rating

No limit, G (all ages), PG (8 and up), PG-13 (13 and up) or R (17 and up). While locked, titles rated above it are hidden from every page, search and Home.

  • The rating comes from the NFO first, then from TMDB; without a US rating, the rating of the UK, Germany, France, Japan or another country or region is converted.
  • Show titles without a rating: off by default. A title whose rating isn't known yet is hidden while locked, unless this is on.
Parental control doesn't encrypt anything

Parental control limits only the CloudDrive2 app on this device. The files can still be opened from other devices, the storage's own app, or a mounted drive. Without App Pro, the libraries and the Media interface aren't available, so parental control has no effect.

Other apps

Emby API for other apps

CloudDrive2 on a Mac, iPhone, iPad, Apple TV, Apple Vision Pro, Android phone or TV, or Windows PC can serve an Emby-compatible API, so tools such as MoviePilot connect to your libraries as they would to an Emby server: they read the titles and people, and fill in the cast's names, biographies and photos. Turn it on under Settings → Media Libraries → Advanced → Emby API for other apps; it is off by default. Meta Quest doesn't have it.

Settings

  • Port: 29801 by default. On iPhone, iPad and Apple Vision Pro it runs only while the app is on the screen.
  • This device only: only apps on this device can connect; when off, apps on your local network can.
  • API keys: make one for each app that connects, and choose the libraries it reaches. Private libraries are reached only when "Private libraries too" was chosen after unlocking with the PIN.
  • In MoviePilot, choose Emby as the server type, then enter the address and a key.

What other apps write

  • People's names, biographies, photos and roles, and Favorites. People's details show before what the NFO and TMDB say.
  • It is kept on this device, never in your media's folders; Clear library data and rescans keep it.
  • With Sync scanned data across devices on, it travels to your other devices with the photos.
  • Only people's details and Favorites are taken for now; a title's own details and pictures are not.
Security

The API uses plain HTTP on your local network, so keep the keys safe. It reaches only the titles and people in your libraries, never your files or your account.

Privacy

What leaves the device

  • CloudDrive's servers: receive nothing from the media library.
  • Information sources: only when their switch and the library's Look up online are both on, and only what the table lists, such as a title and year. File contents, paths and accounts are never sent. Opening an artist or author page sends the MusicBrainz id or the author's name on to Wikidata and Wikipedia.
  • The AI service you choose: only with AI identification on, the chosen libraries' unidentified items' paths below their library folder, their file names, and the tags, cue sheets, SACD text or OPF read from them (Windows sends no table of contents, catalogue numbers or SACD text). Private libraries are never sent. Some services may train on what is sent under a free plan; DeepSeek stores data in mainland China.
  • Your Emby or Jellyfin server: only when you import, it is read with your sign-in: its libraries, titles, people, pictures and your watch history. Nothing is written to it.
  • Apps on your network: only with the Emby API on, apps holding a key can read the titles and people in the libraries it reaches.
  • Your storage: the sync files when sync is on; the scanned-data packs, picture files, and people's photos from other apps and imported servers when Sync scanned data is on; NFO files and artwork when saving them is on; the NFO and pictures in a film's folder when you save Edit metadata….

The sync files are plain JSON text, not encrypted. They hold the libraries' names and folders, the PIN check, identified titles' paths and TMDB ids, Needs review candidates, and each season's intro and ending times. Anyone who can open that storage, including people you share the storage account with and the storage provider, can read them. Choose storage you are comfortable keeping this in. Deleting the CloudDrive2 Sync folder deletes the copies in the storage; devices with sync still on write their own files again.

The scanned-data packs are compressed, not encrypted. They hold the titles' paths, what the NFO files say, what was read from the media files, and the answers of TMDB, MusicBrainz and the like, private libraries' data included; the picture files hold posters and covers. Anyone who can open the storage can read them.

FAQ

Frequently asked questions

My library shows only file names, with no posters or plots

Without NFO files and artwork in the folders, titles need online lookup. Turn on Settings → Media Libraries → Identification → Look up titles on TMDB, and check that the library's Look up online is on; private libraries start with it off. Use Test connection to check that TMDB can be reached; in mainland China, keep the default api.tmdb.org.

A title was identified wrongly. How do I fix it?

Open the title's page, choose Identify…, and pick a candidate or search by title and year. Your choice is kept. If a whole batch of files has the same problem, such as a fansub group's naming or episode numbers, write a recognition word or add {tmdbid=…} to the folder's name.

Why do films without a year often end up in Needs review?

Many films share a title. Without a year, a film is accepted only when both the Chinese and the Latin title in its name match the same film; otherwise you confirm it once. Add the year to the file or folder name, such as Heat (1995), and it is identified automatically.

I already scraped with tinyMediaManager or Emby. Do I need online lookup?

No. NFO files and artwork in the folders come first, and titles whose NFO has an id are identified directly. You can turn lookup off and let the library show only what the folders already have.

Will "Save info and artwork beside the media" overwrite my files?

No. NFO files and images written by other tools are never changed, and a title whose folder already has another tool's NFO gets no files at all. Only with Prefer online info on too, after a confirmation, are other tools' .nfo files and pictures renamed (with .bak added) and replaced with TMDB's; nothing is deleted.

New files don't appear in the library

Choose Refresh on the library page. With the Core Pro feature file change notifications, files added through this device appear by themselves; see Picking up new files by itself. Files added on other devices or in the storage's own app appear when the folder is read again: choose Scan this folder in the library's folder view, or in the file browser, or Scan now in the library's settings, or set how often Scan again runs.

My libraries aren't on my other device

Both devices need Sync libraries across devices on, the same CloudDrive account, and access to the storage holding CloudDrive2 Sync. Without sync, use Export Libraries… and Import Libraries…. The titles, what was read from the files and the posters come with Sync scanned data across devices.

My new device scans the whole library again

Turn on Settings → Media Libraries → Sync → Sync scanned data across devices on the new device and on one that has scanned already. A library the other device scanned completely is taken in whole: no folder is listed, nothing is read or asked again. With Sync libraries across devices on too, a new library is scanned by one device only; see One device scans a library. The first read waits for Wi-Fi or Ethernet unless Sync over mobile data is on. Posters come from the picture packs; on a TV, turn on Download picture packs first.

The cloud reports too many requests, or limits the account, while scanning

Stop scanning libraries in the same storage account on your other devices, and set the library's Listing speed to 1 per second. Then turn on both Sync libraries across devices and Sync scanned data across devices, so each library is scanned by one device. Keep the CloudDrive2 Sync folder in a different storage account from your media files, for example media files on 115 and synced data on 123 Pan. See Keep the cloud from limiting your account.

Does the library change or delete my files?

It never deletes them. The library only reads the folders, and deleting a library or removing a folder deletes no files. Recognition words change only the names the library reads; no file is renamed. The only things written are the NFO files and artwork you turn on, the NFO and pictures you save with Edit metadata…, and the sync files. With both Prefer online info and Save info and artwork beside the media on, other apps' .nfo files and pictures are renamed to .bak, never deleted. What other apps send through the Emby API is kept on the device, not in your files.

The 4K and HDR badges on a poster are outlined

An outlined badge comes from the file name; the file hasn't been read to confirm it. With the library's Detect media info while identifying on (the default), the device that scans it detects them in time; or choose Detect media info on the title's page, or turn on Detect media info in the background under Settings → Media Libraries → Scanning & storage. The badge turns solid once detected.

A library shows Elsewhere or Waiting

Another device scans that library, and this one takes its scan. To scan it on this device, choose Scan now, or turn on Scan this library on this device in the library's settings. If that device is off or offline for 30 minutes, another takes over. See One device scans a library.

Identification got better; what about titles it missed before?

In the library's settings, choose Look Up Again beside Look up unidentified titles again. Titles in Needs review, Not found, or taken for something else are looked up by the new rules, on every device that syncs; identified titles and your choices stay. Folders sorted by a new rule (such as a set of discs) need Scan this folder first.

I sit through the opening of every episode

Playing any episode of the season, open Intro and Ending in the player and choose Set to Now as the opening ends. Every episode of that season skips it from then on, on your other devices too. See Skip intro and ending.

I forgot the parental control code

Choose Forgot code? where the code is asked for, and enter the password of the CloudDrive2 account signed in on this device (and a two-factor code if it has one). Once it is confirmed, set a new code.

My libraries are already organised in Emby or Jellyfin. Do I scan them again?

No: when the media files are on your cloud storage (.strm files aren't supported yet), import them under Settings → Media Libraries → Import from Emby or Jellyfin…. The titles' text, pictures, media info, your watch history and the people are read from the server, the titles play straight from your cloud storage, and no folder is scanned or looked up online. See Import from Emby or Jellyfin.

Does the Emby or Jellyfin server have to stay on after the import?

Not to play: titles play straight from your cloud storage. An imported library reads the server again at each rescan, and keeps what it read last while the server is off; posters and backdrops are fetched from the server when shown, and another picture shows when they can't be. People's photos were downloaded to the device at the import.

Can MoviePilot or a similar tool fill in the cast's photos?

Yes, on a Mac, iPhone, iPad, Apple TV, Apple Vision Pro, Android phone or TV, or Windows PC (not on Meta Quest). Open Settings → Media Libraries → Advanced → Emby API for other apps, make a key for the tool, choose Emby as the server type in the tool, and enter the server address and the key. The names, biographies and photos the tool sends show first; see Emby API for other apps.
