挂载

云盘本地挂载

CloudDrive2 可以把一个云盘，或者云盘里的某个目录，挂载成本地磁盘——就像往电脑上插了一个 U 盘。挂载之后，云端文件不需要事先下载就能直接打开、编辑和保存。

既可以只挂载单个云盘，也可以把多个云盘挂载成一个统一的文件系统。这样在不同云盘之间切换和整理文件时，不必再一个个打开各家的客户端。

更重要的是，挂载出来的盘支持完整的随机读写。任何本地程序都可以像访问本地磁盘一样访问它，无论是办公软件直接保存文档，还是媒体播放器拖动进度条，都不需要先把整个文件拉下来。

  • 完整随机读写
  • 多线程读取
  • 多云盘统一挂载

挂载点数量按会员档位：基础会员最多 1 个本地挂载，核心会员及各档终身版不限数量。见会员与价格。

  • 多线程读取

    读取云盘文件时采用多线程下载，速度成倍提升；在带宽足够的情况下，使用体验接近本地磁盘。

  • 顺带成了同步通道

    在一台设备上改完文件，内容会写回云盘，另一台设备打开时拿到的就是最新版本，不必担心版本不一致或漏改。

一个真正的文件系统，不是只读的镜像

大多数把云盘挂到本地的工具，给出的是一个「能看能拷」的视图：文件属性是挂载时统一设定的固定值，chmod 改不动，扩展属性根本不支持。写入更受限——默认配置下，往一个已经在云端的文件后面追加一行都会失败；要让它成功，得先打开本地磁盘缓存，而缓存的代价是：改动之前必须把整个文件下载回本地。CloudDrive2 的挂载不是这样。

在 Linux 与 macOS 上，挂出来的是完整的 POSIX 文件系统：权限位、所有者与用户组、三个时间戳、扩展属性（xattr），一样不少。在 Windows 上，安全描述符（Security Descriptor）同样完整支持，ACL 照常读写。云盘本身存不下这些东西，所以 CloudDrive2 把它们持久化在本地——改完就在那里，重启之后还在。

写入是真正的随机写。对象存储只能整份替换（上传要带文件哈希），所以改动最终仍然会生成一个新对象；区别在于 CloudDrive2 不需要先把原文件下载回来：它一边从云端取还没改动的那些片段，一边接上你本地写进去的部分，直接拼成新文件传上去。几十 GB 的文件改中间几个字节，不用先花一小时把它拉下来。

就我们所知，把这两件事同时做到的云盘挂载工具，目前只有 CloudDrive2。

  • 完整 POSIX 语义
  • 扩展属性 xattr
  • Windows 安全描述符
  • 随机写入
  • 权限与归属

    权限位、所有者与用户组都真实存在，chmod、chown 改完不会被丢掉——属性持久化在本地，不依赖云盘能不能存。

  • 扩展属性

    依赖 xattr 的程序照常工作——macOS 的 Finder 标记、备份工具的元数据、各类打标签的工具都不会失灵。

  • Windows ACL

    安全描述符完整保留，域环境和多用户机器上的权限设置照常生效。

  • 改一段，不必先下载

    数据库文件、剪辑工程、磁盘镜像这类要就地改写的文件，改动之前不必把几十 GB 先拉回本地。

哪些平台可以挂载

把云盘挂成系统里的一块本地磁盘，需要操作系统本身放行。

可以挂载：Windows 版；macOS 官网下载版（需 macFUSE）；Linux / NAS / Docker 版；已 root 的 Android 设备。

不能挂载：Mac App Store 版（运行在完整沙盒中）；iPhone 与 iPad、Apple TV、 Vision Pro 与 Meta Quest（系统限制）；未 root 的 Android 设备；以及以非 root 用户运行、又没有在 /etc/fuse.conf 里打开 user_allow_other 的 Linux—— 最后这一条改一下配置就能挂载，做法见帮助页。

本页其余的核心功能在这些平台上一样不少。iPhone、iPad 与 Vision Pro 上，File Provider 扩展把云盘接进系统的「文件」应用；Android 上，存储访问框架（SAF）让其他应用直接在系统文件选择器里浏览和打开云端文件。

账户

一次登录，到处使用

CloudDrive2 提供云盘账户的云端同步：你只需要在一个地方登录所有云盘账户，之后在任何设备上的 CloudDrive2 都能直接使用这些账户，不必在每台设备上重新走一遍登录流程。

对于经常换设备的人，这省掉的不只是时间——账号密码输入的次数越少，泄露的机会也越少。家里的电脑、公司的电脑、NAS，用的都是同一套已经登录好的账户。

我们保护你的隐私

同步云盘账户时，账户信息会用你自己的密码做高强度加密之后才上传。我们的服务器不保存你的密码，只保存密码的哈希值用于登录校验。也就是说，服务器手里没有解密所需的密钥，存放在服务器上的云盘账户信息无法被任何人解开。

同时在线的设备数按会员档位：基础会员 2 台，其他各档 5 台。这项限制目前暂不执行。见会员与价格。

协议

WebDAV 服务

WebDAV 是一种基于 HTTP 的文件传输协议，可以像访问本地文件一样访问和管理远程文件，在云盘、网盘和 NAS 领域被广泛使用。

它最大的优势是兼容性：Windows、macOS、Linux 等操作系统，以及 Microsoft Office、Adobe Creative Suite 等应用程序，都内置了 WebDAV 支持。不用装专门的客户端，就能在不同设备之间共享文件。

CloudDrive2 把你所有的云盘封装成一个统一的 WebDAV 服务，任何支持 WebDAV 的客户端都可以通过它访问和管理全部云盘文件。

每个平台都带着这台服务器：手机、平板、电脑、电视和头显上的应用都能各自开启，把本机连接的云盘喂给同一网络里的第三方应用。

强大的 WebDAV 服务管理

在系统设置界面里，WebDAV 服务的各项设置都可以单独控制：

  • 服务控制

    随时打开或关闭 CloudDrive2 的 WebDAV 服务。

  • 账号访问管理

    允许或禁止用 CloudDrive 账号访问 WebDAV，并可以指定这条访问的根目录位置，以及是否只读。

  • 匿名访问控制

    允许或禁止匿名访问，匿名访问有自己独立的根目录位置和访问权限设置。

独立 WebDAV 用户管理

可以创建任意多个独立的 WebDAV 用户，每个用户单独设置自己的根目录位置和是否只读。把某一个目录分享给别人时，不需要交出自己的账号。

这是付费功能

创建独立 WebDAV 用户属于会员功能：月费、年费、轻享终身和终身会员都可以使用，免费的基础会员没有这一项。各档位的具体差别见会员与价格。

分享

用 API 令牌把整台 CloudDrive 接出去

在一台 CloudDrive2 上建一个 API 令牌，任何实现了 CloudDrive API 的客户端，凭地址加令牌就能接进来。另一台 CloudDrive2 是其中一种——「添加云存储」列表里那个叫 CloudDrive 的选项就是它；第三方软件走的是同一套开放的 gRPC API，能力一样不少。

接进来之后，那台机器上连着的所有云盘，在对方看来就是一个普通的云存储：浏览、播放、复制、备份，跟本机直连的云盘走同一套流程。

差别在于「像」到什么程度。WebDAV 是通用协议，代价是只剩文件本身——列目录、读写字节，能力到此为止。走 CloudDrive 令牌，两端说的是同一种语言，云盘的能力就能原样传过来。

  • 缩略图与预览
  • 云端搜索
  • 离线下载
  • 秒传
  • 容量信息
  • 直链
  • 精细授权与有效期
  • 缩略图与预览地址

    远端云盘给出的缩略图和预览地址原样传过来，瀑布流和图库照常出图，不必为了一张缩略图把原文件拉一遍。

  • 搜索交给云端做

    搜索请求转发到远端，再由它交给各家云盘的搜索接口。在几十万个文件里找一个名字，不需要把目录树遍历一遍。

  • 离线下载照常用

    磁力链接和种子文件仍然直接交给远端的云盘去下，任务的添加、查看和清理都能在本机操作。

  • 哈希传过来，秒传才成立

    文件哈希跟着一起传，所以往这个云存储复制文件时同样可能命中秒传。WebDAV 没有哈希这个概念，每一次复制都只能老老实实搬字节。

  • 真实的容量数字

    总容量、已用、可用都从远端取，不是一个占位值——挂载出来之后，系统里显示的剩余空间也就是对的。

  • 直链，绕开中转

    打开之后，本机拿到的是云盘的直连地址，数据不再经过远端那台机器转发。

  • 逐项授权，还能设有效期

    能力多不等于全交出去。每个令牌单独设根目录、有效期，以及每一类操作允不允许——读、写、改、系统、云存储、账号，逐条勾。WebDAV 用户能划的只有根目录和只读两项，也没有到期这回事。

传输

跨云盘文件快速复制 PRO

问题

换云盘服务，或者想在几个云盘之间保留同一份数据，都要面对同一个麻烦：每家云盘的接口和数据格式都不一样，搬家往往要手动操作，速度还受本地带宽限制。数据量一大，时间就长得离谱。

不是所有文件都能走秒传。走不了的时候，CloudDrive2 会直接把文件从一个云盘边下边传到另一个云盘，不在本地磁盘落地。所以本地空间不够、或者中途网络抖动，都不再是问题。

做法

CloudDrive2 的做法是尽最大可能利用云盘的秒传机制。秒传的原理是：上传前先算出文件的哈希值发给服务器，服务器发现这个文件已经存在，就不再接收文件数据，而是直接建一条新的文件记录指向已有的数据。

关键在于，CloudDrive2 可以直接从云盘取到文件现成的哈希值。如果目标云盘和源云盘用的是同一种哈希算法，连计算哈希这一步都可以跳过，于是真正做到秒传。使用相同哈希算法的不同云盘之间，或者同一云盘不同账号之间，效果最明显—— 既省时间，也几乎不占用网络带宽。

  • 不占用本地磁盘

怎么复制

  1. 选中源文件

    在「我的文件」里勾选要复制的文件或文件夹，点工具栏的「移动/复制到...」。

  2. 选目标文件夹

    在弹出的目录树里选好目标目录，点「复制」。目标可以是另一个云盘，也可以是同一个云盘下的另一个账号。

  3. 让它在后台跑

    任务立刻开始，不用守着界面。进度在「任务」页看，「复制任务」和「上传任务」两个标签下都找得到。

本地文件夹也能当源和目标

在「云存储」页点「添加云存储」，在「本地存储」里选「本地文件夹」，把机器上的一个目录加进来。它会和云盘并排出现在「我的文件」里，复制的时候既能当源，也能当目标。

云盘到云盘的复制是核心 Pro 功能。只要有一端是本地文件夹——把云盘上的东西拿下来，或者把本地的东西传上去——所有账号都能用，免费账号也一样。

目标是本地文件夹时，任务显示成「上传任务」

CloudDrive2 把复制统一成一条流水线：读源端，写目标端，写的那一半一律记成上传任务。所以从云盘复制到本地文件夹时，你会在「上传任务」里看到它——方向没搞反，数据确实是从云端下到本地，「上传」只是这条流水线后半段的名字。

事件

文件变更通知 PRO

文件变更通知是操作系统提供的一种机制：文件系统里的文件或目录发生变化时，操作系统会生成一个事件。变化包括创建、删除、移动、重命名以及内容修改。应用程序订阅这些事件，就能在文件变动时立刻做出反应。

挂载盘也有这套机制

CloudDrive2 让挂载出来的云盘文件系统也支持这套机制。挂载盘里创建、删除、重命名或修改文件时，使用 FileSystemWatcher 或 FileNotify 的第三方程序都会收到通知。 Emby、Jellyfin、Plex 这类媒体管理程序，就是靠它来发现媒体目录里多了新片子。

Emby 与 Jellyfin 还可以更进一步：装上 CloudDrive2 伴侣插件，变更通知会直接送进服务器的定向刷新入口，媒体库的「实时监控」就可以全部关掉。

不只是挂载盘

CloudDrive2 还在此之上做了扩展。除了挂载文件系统上的操作，通过 Web 界面修改文件、通过 WebDAV 服务修改文件，以及通过 CloudDrive2 导入离线下载产生的文件变化，同样会生成正确的变更通知。无论文件是从哪条路径进来的，监视目录的程序看到的状态都是最新的。

使用加密功能时请务必遵守各网盘相关的用户协议。因滥用加密功能导致网盘账号被封，CloudDrive 不承担任何责任。

  • 灵活的加密文件夹创建

    可以在任意网盘、或者添加到 CloudDrive2 的本地文件夹里，在任意位置创建任意多个加密文件夹。每个加密文件夹都有自己独立的密码。创建时默认会把密码保存在本机；如果选择不保存， CloudDrive2 重启之后需要重新输入密码才能访问这个文件夹。

  • 强大的加密保护

    写入加密文件夹的所有文件，文件名和内容都会加密之后再保存到网盘或本地文件夹。密码只在本地加密保存，不会同步到 CloudDrive2 的服务器。因此换一台机器登录同一个账号时，访问加密目录需要重新输入密码解锁。

  • 便捷的访问控制

    选中根加密目录后，可以在文件属性页点击锁定按钮把目录重新锁上，下次访问时需要再次输入密码解锁。

    解锁之后，通过 CloudDrive2 访问加密文件和访问普通文件完全一样：支持所有文件操作，可以随机读写，也可以直接在线播放视频。

  • 智能的文件传输

    从未加密的目录往解锁后的加密目录复制或移动文件时，文件会被自动加密后写入；反过来，从解锁后的加密目录往未加密目录复制或移动时，文件会被自动解密后写出。

    如果你想快速秒传加密后的原始文件到别处，可以先把加密目录锁定—— 此时它呈现的就是加密后的原始文件形态，再按普通的文件传输方式操作即可。

  • 商用级加密算法

    文件名加密：使用 AES 加密后再做 UTF-8 编码，保存到网盘的文件名长度限制和未加密时基本一致。

    文件内容加密：采用 chacha20-poly1305 算法，每个文件的加密密钥都根据密码动态生成，各不相同。

    开源透明：加密算法完全开源，解密工具源代码见 github.com/cloud-fs/clouddrive-decrypt。

  • 加密备份支持

    备份任务的目的目录也可以设成解锁后的加密目录，这样备份出来的就是加密数据，为重要数据加一层保护。

密码丢了就找不回来

请务必记住你设置的密码。密码一旦遗忘，文件将无法访问，也无法恢复——没有任何人可以帮你找回。

文件大小限制

为防止加密功能被滥用，月费会员和年费会员保存到网盘的加密文件，单个文件大小上限为 200 MB；终身会员不受此限制；保存到本地文件夹的加密文件也不受此限制。网盘加密文件的大小上限后续会根据实际情况做出适当调整。会员档位的差别见会员与价格。

监控

文件访问监控和权限控制 PRO

CloudDrive2 能告诉你挂载盘上正在发生什么，这是普通文件系统给不了的信息。

  • 看得见谁在读你的盘

    界面里实时显示当前是哪个进程正在访问哪个文件，包括进程的完整路径、文件的完整路径，以及读取网盘文件时的下载速度。哪个程序在偷偷扫盘、哪个任务把带宽吃光了，一眼就能看出来。

  • 不该碰的就别碰

    你可以设定哪些进程允许访问挂载的文件系统，哪些不允许。被加入黑名单的进程无法打开 CloudDrive2 挂载的文件。这能有效阻止不该碰你文件的程序去碰它们，个人用户和企业用户都用得上。

克制

云盘服务商友好

CloudDrive2 在保证使用流畅的前提下，尽量少占用云盘服务商的资源。这不是客套话，而是几条具体的设计。

  • 元数据本地缓存

    文件元数据在本地缓存，用来减少列目录请求，从而降低使用过程中对网盘接口的调用次数。每个目录的缓存时间可以按需要单独设置，你自己在数据时效性和请求频度之间取平衡。

  • 复用已有的哈希

    跨云盘快速复制充分利用云盘已有的文件元数据，尽可能避免重新计算文件哈希，省下大量网络传输。

  • 按需下载，不抢带宽

    读取文件时，下载速度被精确控制在刚好满足读取需要的水平，不会一上来就把带宽占满。这既省了你的网络资源，也减少了对服务商的冲击。

备份

多云盘备份 PRO

重要数据只有一份备份是不够的。多处备份能避免单点故障，某一个云盘服务出问题时，数据仍然是完整、可取回的。

  • 一份源，多个目标

    指定要备份的本地文件夹或网盘文件夹，CloudDrive2 会自动把里面的内容备份到你指定的多个本地文件夹或网盘文件夹。

  • 实时增量

    源文件夹里的文件发生修改时，改动会实时更新到所有备份目的文件夹，任何时候查看备份数据，看到的都是最新状态。

  • 历史版本

    源文件或文件夹被删除、被更新时，每个目标文件夹里对应的文件可以选择保留、删除，或者保留无限多个历史版本。后续版本会支持从任意历史版本恢复文件或文件夹。
